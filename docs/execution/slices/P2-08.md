## 完整行为

1. `X-Request-ID` 仅接受 1–64 位安全不透明字符；不安全、超长或空值均替换为
   本地生成的 128-bit 随机十六进制标识，并贯穿 context、响应头、错误体与日志。
2. 所有非 2xx 响应统一为 `{code,message,request_id,details?}`；状态码与稳定错误码
   固定映射，message 不供分支，任意 cause、SQL、stack、secret 与 PII 均不序列化。
3. 校验详情只允许安全的字段路径与 reason token；非法详情或未知错误码 fail-closed
   为 `INTERNAL_ERROR`。
4. panic、handler 直接写出的非 2xx、以及超过 8 MiB 的非流式响应均由网关收口；
   panic 不逃逸进程，原始 body 不透传。当前平台业务 HTTP 明确不支持 streaming。
5. 每个请求仅写一条结构化 access log：`request_id/account/method/path/status/
   latency_ms/err`。`path` 只允许路由模板，禁止 raw URL、query、body、header 或
   原始错误文本进入日志。
6. 中间件拆为最外层 `RequestIDMiddleware` 与固定尾部 `RecoveryErrorLog`，供
   P2-11 在二者之间按“鉴权 → 并发预算 → timeout”装配，不提前实现安全语义。

## 验收

- HTTP 黑盒使用 `httptest` 验证响应头/错误体/日志一致，以及 raw URL、query、
