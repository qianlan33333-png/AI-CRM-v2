# ADR-011：以行为快照取代旧系统契约回放

## 状态

Accepted（2026-08-10）

## 背景

旧系统只保留 API 调用元数据（路径、状态码、耗时），没有可用于真实契约回放的历史请求体和响应体。继续建设录制中间件或伪造 golden case，既不能证明新旧一致，也会扩大旧系统与生产链路的改造范围。

新版执行方案因此废止真实契约回放路线，改为由新系统黑盒 handler 测试生成实际响应，与仓库冻结的行为快照比较。该机制只保护新系统自身的回归稳定性。

## 决策

1. P0-S10 的空 `contract-replay` 结构门原位更名并改造为唯一的 `snapshot-gate`；仓库、Make 与 CI 不并存两套门。
2. 快照 v1 包含 `operation_id`、`case_id`、请求 `method/path/body` 与期望响应 `status/body`。`operation_id + case_id` 唯一，catalog 按该键排序。
3. 快照 catalog 只能由真实 handler 的黑盒验收测试生成；实际响应只通过标准输入交给 `compare`，禁止提交或手写 actual 文件。重新生成必须无 diff。
4. 易变字段只能进入排序后的精确 JSON Pointer 白名单。通配符、容器级忽略、不存在的字段、未命中实际响应的路径和重复路径全部失败。初始白名单为空。
5. validator 对未知结构字段、重复 JSON key、非法 case、特殊文件、非唯一/乱序 case 与异常格式 fail-closed。比较失败必须给出具体 JSON Pointer。
6. 当前没有业务 handler，catalog 保持零真实快照。第一组真实快照由 P2 stages 样板片生成；P3 每个 handler 片必须附对应 operation 的快照。
7. 不部署旧系统录制中间件，不执行真实企微、生产数据库、部署或真实迁移。

## 被取代的历史条款

- ADR-001 “一次二进制发布需要契约回放控制回归”中的机制名称与旧系统回放含义，由本 ADR 的新系统行为快照门取代。
- ADR-010 第 6 条“行为语义变化同时更新 golden contract”，由“更新对应行为快照且重新生成无 diff”取代。
- v1 执行方案 §5 的 golden case 录制、staging 契约回放与录制中间件路线不再执行；P0–P3 以 v2 执行方案为准。

## 能力边界

行为快照只能发现新系统相对自身冻结行为的回归，**不能证明新旧系统行为一致**。新旧行为差异由 G1 的 API 事实与人工签字承担；真实全功能差异由 P5 人工抽验承担。两处人工门不可被 synthetic、mock 或本地结果替代。

## 后果

- CI 可在没有旧请求/响应素材时建立诚实的回归防线。
- 每个业务 handler 必须维护可审查的稳定响应快照和最小忽略白名单。
- 新旧一致性不再被工具名称暗示为已验证，G1/P5 的人工成本成为显式约束。
