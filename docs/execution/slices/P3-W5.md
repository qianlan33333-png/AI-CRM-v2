# P3-W5：企微事实到 Identity/Contact 集成边界

## 输入与冻结合同

- Base SHA：O2 #182 CLOSED 且四门全绿的 exact main `6c7668bba8a0d0bfdf0d3aa667c94b85c707285f`；W5 已从 W4 main 安全重放。
- W5 只把已完成企微验签/CorpID 校验的 callback inbox 事实，或 W4 官方只读同步事实，转换为冻结的 `identity/port.Ingest` 命令。企微 external userid 使用 `wecom-corp:<corp-id>`、`verified` 与来源 `wecom.callback`/`wecom.sync`。
- Identity 的 I5 `Ingest` 负责 Resolve/Bind、通过 transaction-bound Contact port 建档或追加时间线，以及无法唯一归因时持久化 pending/conflict。WeCom 不直接写 `customers`、`customer_events`、`identities` 或 `pending_events`，也不复制 I5 语义。
- source fact ID 与 CorpID 只用于计算带 domain separator 的 SHA-256 幂等键，保证跨企业不碰撞；时间线 payload 只保留来源枚举，不包含 CorpID、external userid、raw callback 或 source fact ID。

## 本地候选可观察行为

- callback 与 directory sync 两类 verified 事实映射为固定 event type、来源和一个 scoped identity ref。
- 同一企业内同一 source fact 重放构造完全相同的 Ingest 命令，不同 Corp 即使复用相同 source ID 也得到不同 key；Identity 返回的 attributed/pending/conflict 均原样成为稳定终态。
- Identity 事务中断向上返回稳定的可重试错误；再次处理仍提交相同幂等键。非法来源、空/越界/含控制字符输入和未知 Identity 结果 fail-closed。
- `make p3-w5-acceptance` 以 fake Identity port 覆盖两类事实、重复处理、失败后重试、去标识 payload 与负例；不访问数据库或真实企微。

## 运行时阻断与中央序列

- `W2_DURABLE_INBOX_CRITICAL_JOB_PAYLOAD_MISSING`：当前 main 的 W2 只把去标识化摘要写入 `event_log`，没有冻结计划要求的 `inbox_events`、raw verified callback payload 与 `critical` job，无法向 W5 提供 external identity 业务载荷。
- `W4_DURABLE_ITEM_HANDOFF_MISSING`：当前 W4 在返回一页 external userid 前已推进 cursor，未持久化逐项事实或同事务 enqueue；若在交给 W5 前中断，不能仅靠现有 cursor 保证该页逐项重试。
- `I5_INGEST_IMPLEMENTATION_MISSING`：`identity/port.Ingest` 公共合同已存在，但 current main 尚无实现；W5 不提前修改 I5 语义。
- W5 自身不需要 migration、OpenAPI、新 public port 或根依赖，没有修改 O2 已合并的连续 `00016`。O2 #182 已 CLOSED，W5 已安全重放 exact-green main；本 PR 必须重跑 required CI 后才能 match-head 闭环。上述运行时依赖缺口仍需按 I5 中央序列补齐后，才能挂载 callback critical worker 与 W4 durable handoff。
