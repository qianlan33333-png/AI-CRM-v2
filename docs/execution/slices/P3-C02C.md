## 完整行为

1. 闭环 `updateCustomer`、`setCustomerStage`、`addCustomerTag` 与
   `removeCustomerTag` 四个 generated wrapper operation；所有路由都要求
   `customers.write`、有效 session 与 CSRF，成功响应固定 `no-store`。
2. admin/ops 使用 global scope；sales 只允许写自身 `owner_staff_id`。owner
   谓词必须进入 transaction-bound `LockActiveCustomerForMutation ... FOR UPDATE`，
   禁止先查后写造成 TOCTOU 越权窗口。越权与不存在统一 404。
3. PATCH body 使用严格、presence-aware JSON 解码：拒绝未知/重复字段、多个 JSON
   值、非对象和超过 1 MiB；准确区分 omitted 与 explicit null。`gender` 在转为
   PostgreSQL `SMALLINT` 前校验 `-32768..32767`；空 patch 与语义非法值返回 422。
4. stage body 必须且只含 `stage_id`；explicit null 表示清空。tag operation 无 body，
   保持幂等 204。所有返回 Customer 继续复用渠道中立严格转换，不泄露 external
   identity 或底层错误详情。
5. 运行时补齐三个缺失 mutation route，四个写 route 均绑定 CSRF；service/store
   保持同事务 `customer_events + event_log` 与既有幂等语义。
