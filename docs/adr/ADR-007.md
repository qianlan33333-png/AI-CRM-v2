# ADR-007：强类型配置、Secret 与 Extension API Key

## 状态

Accepted（2026-08-08）

## 背景

配置漂移和凭据泄露会直接影响私有化运行。普通设置需要可审计热更新，Secret
则不能进入普通配置、API、日志、源码或历史审计。

## 决策

1. config 模块维护唯一强类型 registry。启动时全量解析、交叉校验，任何未知、
   缺失或非法字段均 fail closed 并只报告字段名。业务模块只读 config port，
   禁止散落 `os.Getenv` 或直查 `settings`。
2. `settings/settings_audit` 只存非敏感配置。审计保存旧值、新值、actor、时间和
   request_id；被 registry 标为 secret 的 key 在写入前即拒绝，而非写后脱敏。
3. WeCom、AI、数据库、JWT、API-key pepper 和 Webhook master key 等 Secret 只从
   受控环境变量或只读挂载文件注入；生产优先文件。它们不支持读 API，不进入
   settings、错误、结构化日志、trace、测试快照或命令行参数。
4. Extension token 格式为 `aicrm_ext_<key_id>.<secret>`；`secret` 由
   `crypto/rand` 生成 32 字节并以无填充 base64url 编码。明文仅创建或轮换成功
   响应展示一次，之后不可恢复。
5. 数据库只保存 key_id、显示前缀、`HMAC-SHA-256(pepper, full_token)`、scopes、
   脱敏 profile、状态及审计元数据。pepper 只来自 Secret source；校验使用
   constant-time compare。轮换创建新 key，旧 key 可显式限时并存或立即吊销，
   不覆盖原 hash。
6. Webhook 签名 Secret 必须与 API key 不同。运行时需要签名的材料使用外部
   master key 派生或加密保存；数据库不得存可直接使用的明文，读接口永不回显。
7. 日志和审计只记录 key_id，不记录 token、hash、Authorization、Cookie、签名
   或回调 payload 中的敏感字段。Secret 扫描和红action测试是合并硬门。

## 后果

- 数据库或普通配置导出不包含可直接使用的 API key。
- 丢失明文只能轮换，不能找回；Secret 变更与普通热更新采用不同流程。
- 部署环境必须安全提供 pepper/master key，否则应用拒绝启动相关能力。

## 备选方案

- API key 明文或可逆加密后直接存库：拒绝，泄库即可调用。
- 低熵 key 加通用密码 hash：拒绝，改用 256-bit 随机 token 与带 pepper 摘要。
- Secret 全放 settings：拒绝，会进入备份、审计与后台读取面。

## 验证要求

- 非法配置和缺失 Secret 必须拒绝启动；数据库、API、日志和审计扫描不得出现明文。
- 创建、并行轮换、吊销、constant-time 校验及 redaction 均须有自动测试。
