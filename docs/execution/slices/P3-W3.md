# P3-W3：企微 Token 与只读分页 Client 边界

## 输入与冻结合同

- Base SHA：`cc2178455fddde7b58f63fae4e594c2f45f72d70`，W2 #176 合并后的 application/go、application/web、policy/repo-contract、security/secret-scan 均为 success。
- W3 只使用企业微信公开的 `GET /cgi-bin/gettoken` 和 `GET /cgi-bin/externalcontact/get`：前者返回 `access_token` 与 `expires_in`，后者在跟进人分页时返回 `follow_user` 与 `next_cursor`。仓内 feature matrix/OpenAPI 没有为该 provider client 冻结新的 v2 管理 operation，因此本片不修改它们。
- 本片不读取旧 Python；接口验证仅指向本地 HTTP fixture，`BaseURL` 必须由调用方显式给出，构造 client 不会选择或请求真实企微端点。

## 可观察行为

- `Credentials`、`CorpSecret`、`AccessToken` 与 `TokenProvider` 是强类型边界；secret/token 的通用格式化始终为 `[REDACTED]`。
- token provider 依据 `expires_in` 缓存，并在到期前刷新；请求超时、传输失败、非 200、畸形 JSON 与企微 `errcode` 分别映射为稳定的 sentinel/API 错误，错误不包含凭据。
- `ExternalContactReader` 只有 `FollowUsers` 一个 `GET` 只读方法，读取最小 `userid` 和 `next_cursor` 投影；不持久化、不排队、不调用 Identity/Contact，也没有写 API。

## 硬边界

- 不修改 migration、OpenAPI、公共 `internal/*/port`、callback 路由、worker、数据库、UI 或根依赖。
- 不编排通讯录/外部联系人同步，不写入 Identity/Contact，不调用真实企微、生产数据库或外发服务。
