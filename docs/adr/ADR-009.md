# ADR-009：Spec-first 与可复现代码生成

## 状态

Accepted（2026-08-08）

## 背景

手写或伪造生成物会让 API、SQL 和客户端在编译通过时仍相互漂移。生成器版本、
输入与输出必须唯一、可复现且能在干净环境重建。

## 决策

1. 生成链固定如下，输出目录禁止手写：

   | 事实源 | 固定生成器 | 生成输出 |
   |---|---|---|
   | `api/openapi.yaml` | oapi-codegen `v2.6.0`（runtime `v1.2.0`） | `internal/api/generated/**` |
   | `api/openapi.yaml` | Orval `7.21.0` + Prettier `3.9.6` (`js-yaml` 4.3.1 / `lodash` 4.18.1 security overrides) | `web/src/api/generated/**` |
   | migrations + `internal/{<domain>,platform}/store/queries/*.sql` | sqlc `v1.28.0` | `internal/{<domain>,platform}/store/generated/**` |

2. generator config、OpenAPI、SQL、migrations 与根依赖清单由 Codex 独占。Pro
   若发现错误只提交报告；修复事实源，不修补输出。
3. `make generate` 必须使用锁定工具，不下载 floating latest。CI 在干净 checkout
   连续生成两次，两次后 tracked tree 均须零 diff；生成缺文件、非零退出、版本
   不符或有 diff 都 fail closed。
4. Go 必须提交真实 `go.sum`；Web 必须提交 npm 11.12.1 生成的
   `package-lock.json`。`go mod tidy` 和 `npm ci` 后不得出现未解释 diff，禁止手写
   checksum、lockfile 或 generator banner。
5. 生成物只包含 transport/DB 适配类型，不承载授权、归因、事务或业务决策；
   手写代码通过 adapter 使用它们，其他域不得导入某域的 sqlc 输出。

## 后果

- 任意精确提交都能复建相同 server、client 与查询代码。
- 修改契约会产生可审查的大型生成 diff，CI 时间增加但阻止伪生成和漂移。
- 生成器不支持事实源时必须先修正契约或拆片，不能临时手写绕过。

## 备选方案

- 不提交生成物：拒绝，难以审查真实 API/SQL 影响且增加构建环境漂移。
- 提交生成物但不做 no-diff：拒绝，无法证明来源。
- 业务层直接使用动态 OpenAPI/SQL：拒绝，牺牲类型和所有权边界。

## 验证要求

- CI 从无缓存 checkout 安装精确版本，连续两次生成并检查全 tracked tree 零 diff。
- 负例必须证明手改生成物、缺锁文件和 SQL/OpenAPI 无法生成时门禁为红。
