## 冻结 DDL 与所有权

- Identity 独占 `identities`、`customer_merges`、`pending_events` 与技术辅助表
  `identity_operation_receipts`。辅助表是 ADR-009 对三核心业务表边界的兼容扩展，
  不缩减 P3-I00，也不得复用 `pending_events`。
- `identities` 唯一 Resolve 键为 `(kind, scope, normalized_value)`；`customer_id` 可空。
  每行持久化 `normalizer_version`、16-byte review fingerprint 与
  `fingerprint_key_version`。raw identity 不设列、不进入 JSON。
- `customer_merges` append-only；保存 pairwise OneID、mode、policy version、脱敏
  fingerprint/key version、actor 和闭集 detail，不保存 match raw/normalized value。
- `pending_events` 只保存内部 `identity_ids`、内部候选 OneID、业务 payload 和状态；
  identity 引用不得复制 raw/normalized value。merge review 候选 root 必须规范升序且
  恰好两个；active review 由 versioned fingerprint 唯一。
- `identity_operation_receipts` 只保存 operation、server-derived scope、32-byte key
  digest、command/result schema version、32-byte payload HMAC/key version、
  `in_progress|completed`、闭集 redacted result 与时间。result 是 object 且不超过
  16384 bytes；不建 GIN/state 索引、不设 TTL。
- deferred commit trigger 拒绝任何已提交 `in_progress`；Down 先删四表再删函数。

## Normalizer v1

- 所有七种 Kind 的初始 `normalizer_version=1`，未来版本新增而不原地重写历史行。
- scope 先 ASCII/Unicode outer trim，固定前缀大小写精确；provider suffix outer trim、
  保留大小写，拒绝内部空白/控制字符。phone 只能是 `phone:e164`。ext suffix 仅接受
  已 canonical 的小写 `[a-z0-9](?:[a-z0-9._-]{0,62}[a-z0-9])?`，大写直接拒绝。
- 非 phone value outer trim、有效 UTF-8、非空、无控制字符；大小写与 Unicode
  codepoint 原样保留，不做 NFC/NFKC。
- phone 仅接受已带国家码的机械 E.164：只移除 ASCII space、`-() .`，之后必须匹配
  `^\+[1-9][0-9]{1,14}$`。拒绝 `00` 前缀、默认国家推断、分机、全角字符与字母。
- fingerprint 输入为 kind/canonical scope/normalized value 的长度前缀编码，
  HMAC-SHA256 前 128 bit；展示为 `hmac-sha256-vN:<22-char-base64url>`。它只用于
  review/audit，不是 Resolve key 或 raw surrogate。

## Receipt 与安全边界

- 逻辑唯一键是 `(operation, server-derived idempotency_scope, Idempotency-Key)`；
  raw key 只在调用栈中存在，数据库仅存 SHA-256 digest。scope 来自稳定认证
  principal/integration，不来自 `IDRef.Scope` 或 request body。
- 唯一 reservation 路径是同一 UoW 的
  `INSERT ... ON CONFLICT DO NOTHING RETURNING`。winner 完成全部事实与 receipt 后同事务
  commit；loser 在未 aborted transaction 的新 statement 读取 completed receipt。
- 禁止 SELECT-before-INSERT、普通 INSERT + 23505 后 SELECT、跨 UoW reservation/
  complete、提交 `in_progress`。同 payload 返回原 result；异 payload 409 且零副作用。
- operation-specific payload HMAC 必须覆盖所有影响结果/审计字段。keyring 来自 typed
  deployment secret source；当前 key 可签名，仍被行引用的旧 key verify-only 保留。
  不得通过 settings、OpenAPI body、日志、错误或 receipt result 注入/导出 key。
- raw identity 全域不持久化。`normalized_value` 仅允许
  `identities.normalized_value` 及必要唯一/精确查询；静态门必须上下文感知，不能用
  全仓 grep 误杀合法列。

## 错误与 HTTP

- 422：Kind/scope/value/phone/normalizer 输入不合法。
- 409：同 receipt key 异规范化 payload，或版本并发冲突；零新增副作用。
- 503：receipt state/schema/result 不合法、历史 HMAC key 缺失或存储不可用；不得猜测
  原结果。错误、日志和 response 不回显 raw/normalized identity、raw key、HMAC 或内部
  database detail。
- Identity mutation 的 `Idempotency-Key` scope 明确为服务端认证 principal/integration；
  Resolve 不创建 receipt。Admin body 仍只能产生 `declared/admin` 证据。

## A2 验收输入

- 原 84 组矩阵加 v3 三项固定为至少 87 组；静态负例命名为
  `raw_identity_forbidden_everywhere`、
  `normalized_identity_forbidden_outside_identities_owned_storage`、
  `normalized_identity_allowed_in_identities_unique_lookup`、
  `fingerprint_not_resolve_key_or_raw_surrogate`。
- PostgreSQL 16.14 双连接永久验证：同 key 同 payload loser 未 aborted 并读取原结果；
  同 key 异 payload loser 未 aborted 后返回 409；普通 INSERT 先得 `23505`、再得
  `25P02` 的负对照。
- reservation、identity/contact/event/event_log/complete/commit 全故障点回滚；进程在
  transaction 内退出不留下 committed `in_progress`；`40001/40P01` 只重试完整 UoW。
