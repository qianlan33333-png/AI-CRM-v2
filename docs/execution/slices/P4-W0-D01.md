## 同一事务生产者闭环

- 触发点只复用 Contact `customer.tag_applied` 真实写。客户标签事实、`customer_events`、
  `event_log`、`event_deliveries(event_id, automation.tag-trigger.v1)` 与 River
  `events_deliver` acceptance 在同一 Contact UnitOfWork；任一步失败五项全部回滚。
- Events-owned `DeliveryAcceptor` 是 Contact 唯一跨域入口；只有 Events store 执行 delivery
  SQL 与 River `InsertTx`。dispatcher/runtime/app/port/test 均不执行事务、SAVEPOINT 或 SQL，
  Automation 不导入 Events store，也不直写 `event_deliveries`。
- 无名旧 dispatcher 继续只处理未 dispatched 且未绑定的事件；实名 consumer backfill
  按缺失 `(event_id, consumer)` 领取，不依赖全局 `dispatched`。因此已派发历史标签事件仍可
  补 Automation，L01 以后也能对同一事件补第二个独立 consumer。

## Automation receipt 与至少一次消费

- `automation_trigger_receipts` 是 Automation 唯一 trigger receipt，以
  `(event_id, consumer)` 唯一；消费同一 UoW 内 reserve receipt、追加唯一
  `automation.triggered`、完成 receipt、完成 delivery。丢响应或 River 重放只返回原事实，
  不生成第二 receipt/event/job。
- 临时错误把 delivery 退回 `pending` 并交给 River 至少一次重试；到达最大 attempts 后只把
  该 consumer 标为 `final_failed`。严格 JSON/语义错误为 poison，只隔离该 consumer；
  `outcome_unknown` 进入终态且再次 Work 不消费、不自动重试；过期 processing lease 可由新
  owner 重领并递增 attempt。
- migration 00025 的 Down 为历史保留 no-op；真实隔离 PG16.14 已通过
  `24 → 25 → 24 → 25`，旧 event、receipt、triggered event、delivery、River job 均不丢。
  最终 catalog 为水位 25、16 个 validated constraints、7 个 valid/ready/live indexes、
  Automation receipt 无跨域 FK、Events 只有到 `event_log` 的域内 FK且无 River FK。
- S 档 20 万真实 receipt 的默认列表 `EXPLAIN` 命中
  `automation_trigger_receipts_list_idx`，没有非法 `Seq Scan on automation_trigger_receipts`。
