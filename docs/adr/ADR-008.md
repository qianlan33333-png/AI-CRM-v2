# ADR-008：Extension API 是定制组件的唯一边界

## 状态

Accepted（2026-08-08）

## 背景

支付、商品和客户小程序等定制需求不能污染核心产品或获得数据库、企微凭据。
同时 v2 需要提供足够小而稳定的插座，让独立组件复用 OneID、自动化和外发能力。

## 决策

1. 定制组件必须位于独立仓库、独立进程，只能通过 gateway 的以下六个端点接入：

   - `POST /ext/v1/identity/resolve`
   - `POST /ext/v1/identity/bind`
   - `POST /ext/v1/events/ingest`
   - `GET /ext/v1/customers/{id}`
   - `POST /ext/v1/outbound/enqueue`
   - `GET /ext/v1/webhooks`

2. gateway 只做鉴权、scope、限流、审计、HTTP 映射和 port 调用；身份决策归
   identity，客户读取归 contact，发送排队归 outbound。组件不得直连核心数据库、
   导入内部 Go 包、自建客户 ID 映射或直接调用企微写 API。
3. v2 核心范围仅含 Extension 插座、API key、脱敏读取、投递状态和签名 Webhook。
   支付、商品、订单履约等业务模型、页面、回调适配器均不进入核心。
4. `/examples` 可保留无真实凭据、默认 fake 的支付 mock，且必须从核心构建、镜像、
   Compose 和部署清单排除。它只证明契约，不构成支付或生产验证。
5. Webhook 地址和 Secret 由受控后台管理，Extension API 只读状态；语义和安全
   约束遵守 ADR-006/ADR-007。

## 后果

- 核心保持统一版本，客户定制件可独立演进和故障隔离。
- 定制件不能绕过限速、归因、审计或脱敏；跨进程调用带来可接受的网络开销。
- 新增第七个端点或核心业务模型必须先新增 ADR，不得借 Slice 顺手扩面。

## 备选方案

- 把客户定制代码放入核心模块：拒绝，版本和安全边界会持续分叉。
- 共享数据库或企微 Secret：拒绝，绕过所有权、限速和审计。
- 通用插件运行时：拒绝，当前规模不需要其运维与隔离复杂度。

## 验证要求

- 架构检查拒绝 `/examples` 进入产物、gateway 出现定制业务表或非 outbound 企微写。
- 六端点逐项做 scope、审计、脱敏和 mock 契约测试；mock 证据只标 synthetic。
