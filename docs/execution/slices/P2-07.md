## 完整行为

1. dispatcher 以 `FOR UPDATE SKIP LOCKED` 按 ID 领取未分发事件，每批 100 条；
   多 dispatcher 可并发领取不重叠批次。
2. 每条事件在同一 PostgreSQL 事务内通过 River `InsertTx` 写入
   `event` 队列，随后才标记 `event_log.dispatched=true`；事务回滚时两者一并回滚。
3. `dispatched` 只表示持久化投递 job 已同事务写入，不表示业务消费成功。
   投递为 at-least-once，subscriber 必须按 event ID 或幂等键做持久化去重。
4. delivery router 允许同一事件类型注册多个 subscriber；无 subscriber 时
   fail-closed，不把空路由冒充业务处理完成。
5. 唯一 scheduler 目录每秒投递 `events_dispatch` 到 `event` 队列；
   `events_deliver` 以 event ID 为 args 唯一键，所有 enqueue 均显式指定队列。
6. `DeferredEnqueuer` 只允许绑定一次，绑定前或二次绑定均 fail-closed，
   仅用于解决 worker registry 与 River client 的构建顺序。

## 验收

- 单元/合同：领取、标记、回滚、空路由、多 subscriber、队列与唯一选项、
  typed-nil 与延迟绑定均覆盖。
- PostgreSQL 16.14 真实验收：子进程在 River `InsertTx` 后、event 标记/事务
  commit 前被 `SIGKILL`；新 client 重启后证明 1 个 job、1 次消费、无 default 队列。
- 真实 PostgreSQL 双 dispatcher 并发领取 200 条事件，证明 200 条均且仅被
  领取一次，生成 200 个不同 args 的 `event` 队列 job。
- 永久负例拒绝 P2-07 验收目标与 `ci-go` 断开、空实现、核心/证据收据漂移。
