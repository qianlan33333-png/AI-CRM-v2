## 完整行为

1. 只闭环 `GET /api/v1/customers/{customer_id}/events` 一个 generated
   operation；默认 50、最大 200，响应固定 non-null `items` 与 nullable
   `next_cursor`，成功响应 `no-store`。
2. 排序固定为 `(occurred_at DESC, id DESC)`；cursor 使用无填充 canonical
   base64url，绑定版本、operationId、固定排序、customer ID、owner scope 和
   最后一项 `(occurred_at,id)`。非法、跨客户或跨 scope cursor 返回稳定
   `CURSOR_INVALID`，不得退回第一页。
3. admin/ops 使用 global scope；sales 仅可读取自身 owner 客户。客户存在性、
   `NOT is_deleted`、owner scope 和 keyset 条件必须进入同一条 SQL；越权、已删除与
   不存在统一 404，禁止先查后读造成枚举或 TOCTOU。
4. SQL 只取 `limit+1`，禁止 OFFSET 与 COUNT；必须命中
   `(customer_id, occurred_at DESC, id DESC)` 索引。每条结果严格验证正 ID、匹配
   customer ID、非空合法 event_type/actor、UTC occurred_at 和 JSON object payload；
   任何存储污染 fail-closed 为 503，不返回底层错误或部分页。
5. HTTP 只使用冻结 generated wrapper 与 `customer.events.read` 能力；运行时接入
   真实 UoW/store/service/handler，不修改 OpenAPI、鉴权模型或公共 port。
