# 周期权益历史最小落表决策

## 状态与范围

本次实施用户已确认的“V1只读、V2分域正式落表、独立入口待人工验收”计划。
111由主线预留，发布须等待110渠道包及自身候选/合并后精确SHA门禁。
2条周期定义、93条权益、118条事件的真实归档形状预检通过；预检不是迁移完成。

## 决策

复用已验证静态导入的 `products` ID，追加Product-owned历史扩展、权益、事件三表。
历史定义 → 原Product；历史权益 → 历史定义；历史事件 → 历史定义/可空历史权益。
客户只通过冻结DM01关联；订单只通过同归档Finance回执关联；未关联保留NULL，冲突停止。
source id仅用于历史来源和幂等，不作V2主键。原unionid/外部联系人快照继续在加密归档，
不复制为公开身份字段。原状态/负调整天数/可空日期按源保留，不推断新状态转换时间。

不改变现有商品status/version，不写当前Member Grid、local entitlement或event_log。
caller-bound writer/store/journal同事务；重复导入核对完整静态事实与target digest。
只读列表复用周期页面历史区，不提供购买、授权、续费、分享或撤销历史权益的按钮。

## 取舍

- 直接转当前member：缺少真实expired_at和可对应的manual/paid_order语义，拒绝造新授权。
- 重分类旧Product：会使Finance普通Product Reader读不到，且CAS会改变已封账version，不采用。
- 只留归档：不能让用户逐项浏览，故增加三张窄历史表和小型只读接口。

代价是历史成员与当前成员分开显示，需明确“V1快照状态”。无新数据库、同步平台或风控框架。
2534条HXC使用快照没有productID，不强挂某周期；协作者/分享记录不恢复权限。

## 验证与停止点

领域测试、PG同事务回滚、真实归档导入/重放/两次对账、旧Product/Finance不变证明、
鉴权只读API及页面空态/失败态/真实字段测试。正式写入只在V2；V1零修改、现网零切换。
全部板块具备入口、数据、账号、回滚材料后停止，等待用户人工最终确认。
