  仅首次新建时同事务追加一条 `identity.created`。

## 冻结行为

- Kind 仅为 `wecom_external_userid`、`unionid`、`mp_openid`、`oa_openid`、
  `alipay_user_id`、`phone`、`ext`；对应 scope 分别必须为非空的
  `wecom-corp:`、`wechat-open-platform:`、`wechat-app:`、`wechat-app:`、
  `alipay-app:`、精确 `phone:e164`、`ext:` 命名空间。scope 不能含空白或控制字符。
- 非 phone 的 opaque value 只去除首尾空白，保留大小写；phone 仅接受 E.164，允许
  输入中的空白、`-`、`.`、`(`、`)` 分隔符，规范化结果必须为 `+` 加 2–15 位数字。
  raw 输入不会进入表、事件、错误或日志。
- normalizer 固定版本为 `1`。SQLC query 的唯一可变绑定严格为 `$1` kind、`$2`
  scope、`$3` normalized value；没有动态 SQL、ORM 或第二份规范化器。
- `identities.customer_id` 始终为 NULL；本片不 Resolve、不 Bind、不 Ingest、不创建
  receipt/review、不合并客户。
- SQL `ON CONFLICT (kind, scope, normalized_value)` 返回唯一既有或新建 ID。新行才在
  同一 UoW 追加 `identity.created:<identity_id>`，payload 只含 identity ID、Kind、
  scope 与 normalizer version，不含 raw/normalized value 或 customer ID。
- 任一 store/event 错误必须使 identity 与 event 一并回滚。
