# P3-S01：Segment DSL typed AST 与 fail-closed parser

## 输入合同

- Base SHA：`1ffeaba45c72a0e53a8763788cda1992ff253d24`（latest main；P3-S00 已 closed）。
- 只实现 `internal/segment/dsl` 的闭合 typed AST、JSON parser、validator、canonical JSON
  与结构化错误；不修改 S00 的 DDL、OpenAPI、跨域 port 或 table ownership。
- `S00` 是 DSL v1 的唯一语义来源。本片不引入新 field、operator、error reason 或隐式条件。

## 可观察行为

- `Parse([]byte)` 只接受一个闭合 JSON AST：`and`、`or` 或 predicate；所有 object key
  由 token 流读取，重复 key 在进入 map 前拒绝，绝不采用 last-key-wins。
- AST 的 node/value interface 均为 sealed；仅包含 group、predicate、正 int、正 int list、
  UTC timestamp、relative days 与 boolean。解析器不导入 SQL、store、pgx、River、HTTP 或
  其他 domain。
- parser 保留 group 子节点输入顺序；`in/has_any` 正整数列表升序规范化，重复元素返回
  `segment_definition_noncanonical_value`。RFC3339 的零偏移时间规范化为 UTC `Z`。
- 所有错误只返回 S00 冻结的 stable reason 及 RFC 6901 JSON Pointer；错误中不含原始
  DSL、SQL、bind args 或 customer ID。

## 硬边界

- 最大定义 64 KiB、深度 8、节点 128、group children 64、所有 integer list 总元素 1000、
  单个 string 64 bytes；超限统一 fail-closed。
- `stage_id/owner_staff_id/channel_id` 只允许 `eq|in`；`tag_id` 只允许 `has_any`；
  `added_at/last_interact_at` 只允许 `before|after`；`is_deleted` 只允许 `eq`。
- 不实现 S02 SQL compiler、任何 raw SQL/ORM/执行器、成员物化、refresh、River、handler、
  UI、OpenAPI 或 migration；真实三人群包 diff 仍为 `PENDING_EXTERNAL_GATE`。

## 验收矩阵

- 合法：所有 field/operator/value family、group nesting、UTC time、relative day、排序
  canonicalization 与 canonical round-trip。
- 非法：malformed JSON、duplicate/unknown key、未知 field、错误 operator/value、SQL-shaped
  field、empty group、重复整数、非 UTC time、超深/超节点/超列表/超字节。
- fuzz/property：任意 bytes 不 panic；成功解析的 canonical JSON 必可重解析且字节稳定。
