## 完整行为

P3-C06B 首轮完整矩阵在授权测试机完成 4,096 场景，80 个场景的 P95
`>=200ms`；最慢场景 P95 `460.673967ms`。生产 `ListCustomerIDsBounded` 的
单份 EXPLAIN execution time 最高 `426.547ms`，而页面查询最高
`97.459ms`。该 bounded 查询每次把最多 10,001 个 ID 从
PostgreSQL 传到 Go，但调用方只使用切片长度表达精确 10k 或 10k+，在约十万次
repository 调用的硬门中造成不必要的网络、解码与分配开销。

本片保持页面、筛选、watermark、cursor、精确 10k/10k+ 与响应语义不变，把
bounded total 改为数据库内对“先 LIMIT 10,001 的匹配集合”聚合，只传输一行
`bigint`。不得改为无上限全量 COUNT；返回缺行、多行、负数或超过 10,001 时
repository 必须 fail-closed。

## 验收

- sqlc 连续生成两次无 diff。
- focused store race/vet 与真实 PG acceptance 覆盖 0、精确值、10k+ 及非法聚合
  形状；筛选和 keyset 语义不得变化。
- 从新的精确 main SHA 重建 generator/runner，在同一 2C4G、PG16.14、20 万数据
  与 4096 场景上从头执行 P3-C06B；只有 P95 `<200ms`、无目标 Seq Scan 且
  离线收据验证 PASS 才能关闭硬门。

## 规模与回滚
