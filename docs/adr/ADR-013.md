# ADR-013：单实例私有化部署语义

## 状态

Accepted（2026-08-14）

## 背景

AI-CRM-v2 只用于单实例、单企业、单 PostgreSQL 数据库的私有化部署。
一个部署单元只服务一家企业；企业边界由部署和数据库边界提供，不由
应用层 tenant 字段提供。以往文档和源映射中的 `tenant_id` 只记录旧系统事实，
不得被推导为 v2 的 SaaS 多租户产品模型。

## 决策

1. 部署模型固定为单实例、单企业、单数据库。核心与兼容层均不建设
   tenant model、tenant selector/switch、tenant RBAC、tenant 列、tenant 复合索引、
   tenant public port 或跨租户测试。
2. actor 身份、RBAC/capability、session/CSRF/安全 redirect、数据归属、
   actor/业务幂等、ownership/UoW、支付与外部效果边界继续生效。
   数据安全与越权仍是红线，但不建设或验收 SaaS 跨租户隔离。
3. `docs/migration-mapping.jsonl` 中含 `tenant_id` 的 28/316 行是不可回改的
   源事实。后续目标片只能以 `DROP_SOURCE_SCOPE` 或单一部署常量销账，
   不得因此创建 v2 tenant 列、索引、port 或选择器。
4. `docs/api-mapping.jsonl` 中含旧 `tenant_id` 入参的 2/781 行同样只是
   源事实。Legacy Compatibility API 可为保持旧请求形状而接收该参数，
   但必须忽略其选择语义，不得向 domain、store、SQL 或公共 port 传播。
5. `admin_users.provider_tenant_id` 与 `VerifiedLogin.TenantID` 是已合入的历史命名；
   它们当前只表示企微 provider identity namespace，不表示 SaaS tenant。
   命名清理必须在非生产 PostgreSQL 16.14 先验证 CorpID 语义，再以新的
   连续 migration 前向完成；不得回改 `00004_auth.sql`。

## 治理边界

- 本 ADR 只前向约束新实现与新验收；历史 evidence、ledger、旧 migration
  和源映射保持原样。
- 不因单实例模型削弱 actor 授权、数据归属、事务原子性、幂等、支付、
  外部效果或生产操作红线。
- 不新建泛化 provider/SSO、运维 UI、dashboard、恢复器或新产品能力。

## 验证要求

- repo-contract 必须锁定本 ADR 与三份活跃执行文档的单实例语义，并永久
  拒绝将 tenant 产品能力或跨租户验收恢复为 P4 要求。
- repo-contract 必须证明源映射仍恰好是 28/316 和 2/781，不改写其内容。
- 本治理片不改运行时 Auth、migration、旧 UI、业务 DTO 或功能终态，
  不计入 781/293/316 业务进度。

## 后果

- P4 业务片只围绕单企业内的 actor、数据归属和业务幂等设计。
- 源系统 tenant 形状不再驱动 v2 数据模型，减少每个后续 slice 重复建模、
  索引与跨租户测试。
