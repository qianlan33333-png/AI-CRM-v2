## OpenAPI 与 RBAC 冻结

1. `GET /api/v1/stages` / `listStages`：`stages.read`，admin/ops/sales
   均为 `global`。stages 是全局定义，不伪造 owner scope。
2. `POST /api/v1/stages` / `createStage`：`stages.write`，admin/ops
   为 `global`，sales 明确 deny；成功返回 201。
3. `PATCH /api/v1/stages/{stage_id}` / `renameStage`：`stages.write`，
   admin/ops 为 `global`，sales 明确 deny；成功返回 200。
4. 两个写操作必须带冻结的 43 字符 `X-CSRF-Token`，服务端
   必须校验它与当前 opaque session 的存储 hash 绑定；禁止只检查
   header 存在、只做 double-submit 或把 token 传入日志/响应。
5. `Stage` 固定返回 `id/name/sort_order/config`；create 只必填
   `name`，`sort_order` 缺省为 0，`config` 缺省由 service 规范化为 `{}`；
   rename 只修改 `name`。不新增名称长度、sort order 正数或 config
   object-only 一类无证据限制。

## Handler 与快照合同

- handler 必须从已验证 principal 生成 `admin:<admin_user_id>` actor，
  不接受客户端 actor；直调时缺少精确 authorization 也必须 fail-closed。
- JSON 未知字段、多个顶层值、非法 stage ID 与 service 校验失败分别
  稳定映射为 400/422；不存在为 404，唯一冲突为 409，依赖失败
  为 503，不泄露底层错误。
- API runtime 装配真实 stage repository/service/event appender，写路由
  Authenticate → 服务端 CSRF 绑定校验 → Authorize → budget → timeout →
  recovery/error/log 进入 handler。
- ADR-011 首组 catalog 由真实 generated HTTP wrapper + stages handler 黑盒
  生成 actual，只通过 stdin 交给 `snapshot-gate compare`；仓库不跟踪
  actual。快照只证明新系统自身回归稳定，不宣称新旧一致。
