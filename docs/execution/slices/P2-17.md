## 页面与权限合同

1. `/stages` 对 authenticated admin/ops/sales 均可见，三角色都使用
   `stages.read/global`；sales 只读，admin/ops 才显示新增与改名控件。
2. 初次进入页面调用已生成的 `listStages`，固定 `credentials=same-origin`；
   按服务端 `sort_order,id` 顺序显示，不在浏览器伪造二次排序。
3. 初始 loading、空列表、成功、依赖失败与重试必须可区分；列表响应结构
   不合法时 fail-closed 为 unavailable，不渲染半真数据。
4. 新增只提交 `name` 与可选 `sort_order`，config 使用后端缺省 `{}`；改名
   只提交 `name`。名称不得由 UI 擅自 trim 后静默改义；空白只做客户端提示，
   最终判定仍以 422 为准。
5. 写请求从既有 `aicrm_csrf` cookie 读取精确 43 字符 token，放入
   `X-CSRF-Token`；不得渲染、记录或持久化 token。缺失 token 必须本地
   fail-closed，且不发请求。
6. 不做 optimistic mutation。成功后以服务端返回 Stage 更新列表；请求中
   禁用重复提交。401 触发父 shell session 失效；403 显示权限已变化；
   404/409/422/503 与网络错误给出稳定中文提示且允许安全重试。
7. 页面保持单一 h1、label/fieldset/status/alert 可访问语义、键盘可操作；
   不引入弹窗库、状态库或新依赖。

## 冻结的页面模块边界

- `web/src/stages.ts`：生成 client 的窄 transport、响应严格解析、状态与 mutation
  结果分类；禁止复制或手写 HTTP path。
- `web/src/stages-ui.tsx`：props 驱动的 `StagesPage`，可注入 transport、cookie
  reader 与 `onUnauthenticated`，生产缺省使用生成 client。
- `web/src/main.tsx`：仅由 Sol 把 `/stages` route 接入 `StagesPage`，并把 401
  回传绑定到现有 session/cache 失效路径。
- `web/src/auth.ts`：仅由 Sol 将 `/stages` 加入三角色已冻结导航权限；不改变
  登录、cookie、session 或 secret 模型。
