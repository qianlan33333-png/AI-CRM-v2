# ADR-014：Campaign 批准交接的 Outbound 本地接纳边界

## 状态

Accepted（2026-08-23）

## 背景

Campaign `00067` 只创建已批准的本地交接事实，不创建 Outbound 发送任务。
现有 `EnqueueOne`、`EnqueueBatch` 会创建 `outbound_tasks` 和 River 发送 job，
不能用于接纳批准交接。未绑定事件也会被通用 dispatcher 放入 Events River 队列，
因此接纳事件必须具有明确且无外部效果的 consumer。

## 决策

1. Campaign 提供窄的 transaction-bound locked reader，只返回已批准 handoff 及其
   immutable plan targets/steps/digests。Outbound 不读取 Campaign 私表；composition
   root 是唯一 DTO 映射点。
2. `00068` 只写 Outbound-owned header、step snapshot、customer task link 和
   actor-scoped durable receipt。接纳初态固定为 `held/not_evaluated`，不创建
   `outbound_tasks`；`blocked/pending` 和 `eligible/inactive/contact_policy` 仅冻结未来
   受控状态闭集。
3. POST accept 的 reservation、snapshot copy、
   `outbound.campaign_handoff_fact_recorded`、strict readback 与 receipt completion
   位于同一 UoW。replay 只读取 receipt 的 durable safe result，不读取当前 review。
4. 新事件绑定 `outbound-campaign-handoff.fact.v1`。consumer 只在独立 UoW 完成
   Events delivery receipt。它会产生内部 Events delivery River job，但不会产生
   Outbound send job、调用 Provider 或声称送达。
5. 本片不注册 dispatch/release API。未来 dispatch 必须在同一 reservation UoW
   调用 Contact EligibilityChecker（checkpoint=`dispatch`）并持久化
   `eligible/inactive/contact_policy`，且 Provider 调用不得位于数据库事务内；该能力
   当前为 `EXTERNAL_GATE`。

## API 与安全投影

- `POST /api/admin/outbound/campaign-handoffs/{campaign_code}/{plan_id}/accept`
- `GET /api/admin/outbound/campaign-handoffs/{campaign_code}/{plan_id}`
- `GET /api/admin/outbound/campaign-handoffs/{campaign_code}/{plan_id}/reconciliation`

POST 使用 `operations.manage`、session CSRF 和 actor-scoped `Idempotency-Key`；GET
使用 `operations.read`。响应只包含本地 header、计数、状态和固定安全布尔值，不包含
customer IDs、step content、provider message id/code、last error 或 raw identity。

## 备选方案

- 复用 `EvCloudCampaignFact`：拒绝，会污染 Campaign 事件所有权。
- 复用未绑定 `EvOutboundAccepted`：拒绝，其既有语义对应 `outbound_tasks`，且会走
  通用 Events job。
- 调用 `EnqueueOne/Batch`：拒绝，会越过真实 dispatch 前的 Contact policy gate。

## 验证要求

- PostgreSQL 16.14 验证 `00001→00068→down→up`、facts down guard、reserved commit
  `23514`、tampered snapshot/event、cross-campaign、双连接单赢家及 replay 无重复。
- 证明 accept 后没有新增 `outbound_tasks`、Outbound send River job 或 Provider 事实；
  只允许明确绑定的内部 Events delivery job。
