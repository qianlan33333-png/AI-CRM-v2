## 1. 背景与单一目标

AI-CRM v2 最终只有一个 `aicrm` 二进制，但必须能明确隔离 API 与 worker
故障域。本 Slice 只实现标准库 CLI 与进程生命周期编排，使后续 Slice 能把
HTTP 和 River adapter 注入冻结 slot。

日志中间件或业务模块。证据层级只能写 `LOCAL SKELETON`。

## 4. CLI 合同

`--role` 必填且没有 env/default fallback。只接受：

- `--role=api`、`--role api`
- `--role=worker`、`--role worker`
- `--role=all`、`--role all`

大小写敏感，不 trim，不接受 `api,worker`。`--help` 或 `-h` 必须作为唯一参数，
向 stdout 只输出以 `runtime.UsageLine` 开头的帮助，stderr 为空，退出 0，不启动
component。

| 情况 | stderr 第一行 | 退出码 |
|---|---|---:|
| 无参数 | `aicrm: --role is required` | 2 |
| 空/未知/大小写/组合 role | `aicrm: --role must be one of api, worker, all` | 2 |
| 未知 flag、位置参数、重复 role、help 混入其他参数 | `aicrm: invalid arguments` | 2 |

所有 usage error 随后输出 `runtime.UsageLine`，不得回显原始非法值。运行错误或
shutdown timeout 退出 1；正常信号关闭退出 0。不得使用 `log.Fatal` 隐藏退出码。

## 5. 生命周期合同

- 启动前先验证 role 及全部被选 component。`all` 缺任一 component 时，在启动
  任何 component 前返回可由 `errors.Is` 识别的 `ErrMissingComponent`。
- `api` 只调用 API 一次；`worker` 只调用 Worker 一次；`all` 并发调用两者各
  一次。未选 component 调用零次。
- 父 context 未取消前，component 返回 `nil` 或 `context.Canceled` 都是
  `ErrUnexpectedStop`，不得当成成功。
- 任一 component 返回真实错误时立即取消 sibling，等待其退出，并保留原错误。
- 首个 SIGINT/SIGTERM 取消父 context。全部 component 在
  `runtime.ShutdownGrace` 内仅返回 nil/context cancellation 时，整体成功。
- shutdown 期间的真实 component error 不能被信号吞掉；超时返回可由
  `errors.Is` 识别的 `ErrShutdownTimeout`，并指出未退出 slot。
- 多错误输出顺序固定为 API、Worker；不能由 goroutine 竞态决定。
- panic 不 recover；第二次信号、SIGHUP reload、SIGKILL 不在本片。
- 可用未导出的、可注入短 grace 的 helper 做 timeout 单测；公共合同不得扩展。

`components.go` 里的两个临时 component 只能等待 context 取消。禁止监听端口、
建 goroutine 脱离父生命周期、连接网络/数据库、注册 River/worker/scheduler、
读取 env/settings，或输出 ready/healthy/initialized 等误导信息。

## 6. 禁止 import/调用

本片代码不得出现 `net`/`net/http`、pgx、River、`os.Getenv`、`time.Ticker`、
`time.AfterFunc`、第三方 CLI/signal/errgroup 包。graceful shutdown 可使用标准库
context、signal、sync、time.NewTimer 和 errors。
