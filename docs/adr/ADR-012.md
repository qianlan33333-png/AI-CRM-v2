# ADR-012：Identity 持久化边界与操作收据

## 状态

Accepted（2026-08-13）

## 背景

ADR-002～004 和 P3-I00 已冻结 OneID、归因与合并语义，但尚未决定 Identity
持久化时如何隔离身份数据和命令幂等。把技术收据塞进 `pending_events` 会让业务
replay 与命令状态相互污染；把 raw、normalized 与脱敏 fingerprint 混作一种
值又会扩大 PII 暴露面。

本 ADR 只冻结后续切片共同依赖的持久化裁决；不创建迁移，也不实现任何运行时。

## 决策

1. Identity 业务表固定为 `identities`、`customer_merges`、`pending_events`；另设
   identity-owned 技术辅助表 `identity_operation_receipts`。后者不是业务队列、
   review 或 River job 表。
2. `pending_events` 只承载 attribution、conflict 和 merge-review；不得复用为 operation receipt，也不得由 pending replay 提交或消费 receipt。
3. raw identity 不进入持久化、事件、收据、错误或日志。normalized identity 只可存在于 identity-owned `identities` storage；fingerprint 是版本化、脱敏的
   审核/审计引用，既不是 Resolve 键，也不是 raw 或 normalized 的替代存储。
4. receipt 的 reservation、业务写入、event_log 与 completed result 必须在同一 transaction-bound UoW。唯一 reservation 算法为 `INSERT ... ON CONFLICT DO NOTHING RETURNING`：返回行的请求拥有 reservation；未返回行者只可在同一未
   aborted UoW 的后续 statement 读取已提交的 completed receipt。禁止
   SELECT-before-INSERT、捕获普通 `23505` 后继续、跨 UoW reservation/complete，
   或提交 `in_progress` receipt。
5. receipt 不设 TTL；不得被 River/periodic worker 扫描；不得建立 GIN 或仅按 state 的索引。任何 retention、队列化或新索引均须另行 ADR 和切片。
6. `customer_merges.detail` 是闭集、脱敏的审计对象：仅可表示 policy version、
   `auto|manual` mode 与版本化 fingerprint 引用；不得保存 raw、normalized、
   任意扩展 JSON 或 PII。

## 后果

- R3B 只负责以 migration `00010` 实现四表 DDL、ownership 与数据库验收。
- R3C 只负责将本 ADR 的 privacy/anti-pattern 变为永久正负门。
- R3D 只负责 ports、HTTP/keyring 和 fail-closed 密钥合同；normalizer、fingerprint
  计算、receipt repository/UoW 与 Resolve/Bind/Ingest 均不在本 ADR 实现。

## 备选方案

### 复用 pending_events

拒绝。业务 replay 会获得技术状态机的写入和消费路径。

### 进程内幂等缓存

拒绝。它不能覆盖重启、多进程或提交成功但响应丢失。

## 验证要求

- R3B 必须在 PostgreSQL 16.14 上验证 migration `00001→00010→down→up`、catalog、
  constraint 与 owner；不得连接生产库。
- R3C 必须永久拒绝 raw、pending receipt、TTL、River、GIN、`in_progress` commit
  与非闭集 merge detail。
