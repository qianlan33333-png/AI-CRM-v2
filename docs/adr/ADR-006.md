# ADR-006：统一 HTTP 契约、权限范围与 Webhook 语义

## 状态

Accepted（2026-08-08）

## 背景

v2 同时服务后台用户、销售和外部扩展。若错误体、分页、数据范围或
Webhook 语义由各模块自行决定，客户端会漂移，owner 越权、SSRF 和重复消费
也难以统一防守。

## 决策

1. `api/openapi.yaml` 是 HTTP 唯一事实源，由 Codex 冻结；实现不得另造端点、
   字段或状态码。每个 operation 必须声明稳定 `operationId`、权限和 owner scope。
2. 所有非 2xx 响应使用同一结构：

   ```json
   {"code":"VALIDATION_FAILED","message":"可安全展示的信息","request_id":"opaque","details":[{"field":"name","reason":"required"}]}
   ```

   `code` 是稳定机器码；`message` 不作为程序判断依据；`request_id` 非空并与
   `X-Request-ID` 一致；`details` 可省略且不得含 SQL、堆栈、Secret 或 PII。
   固定分类为 400 malformed/cursor、401 unauthenticated、403 unauthorized、
   404 not found、409 transport conflict、422 validation、429 budget、500 internal、
   503 dependency unavailable。`Resolve/Bind/Ingest` 的已定义业务状态不是传输错误。
3. 列表只接受 `cursor` 与 `limit`。`limit` 默认 50、最大 200；禁止 `offset/page`。
   cursor 是无填充 base64url 编码的版本化载荷，包含 operationId、固定排序、
   `(sort_value,id)` 和过滤条件指纹；客户端必须视为不透明。operation、排序或
   指纹不匹配返回 `CURSOR_INVALID`，不得降级到第一页。owner/RBAC 过滤必须先于
   keyset 条件进入同一 SQL。
4. 后台角色为 `admin/ops/sales`。operation 逐项授权；`sales` 的客户对象必须
   满足 `owner_staff_id = auth.staff_id`，列表和单对象查询均在服务端强制，非本人
   对象返回 404 防止枚举。客户端传入的 owner filter 不能扩大授权范围。
5. Extension API 只使用六个最小 scope：`identity:resolve`、`identity:bind`、
   `events:ingest`、`customers:read`、`outbound:enqueue`、`webhooks:read`。
   `customers:read` 还必须应用该 key 绑定的脱敏 profile；全量调用写审计。
6. `GET /ext/v1/webhooks` 仅返回当前 key 可见的订阅、启停状态和投递摘要，不能
   创建、修改或返回完整回调 Secret。回调地址只能经 admin 受控配置；仅允许
   HTTPS，禁 loopback、私网、link-local、metadata 地址，初次保存及每次投递均
   复核 DNS。投递端必须在实际 `dial` 的每个 IP 上重新执行相同拒绝规则并固定
   已核验地址，连接后核对 remote address；默认禁重定向。若未来允许重定向，
   每一跳必须重新执行 URL、DNS、dial IP 与主机校验，禁止校验后换址的 TOCTOU。
7. Webhook 是至少一次投递，不承诺顺序。每个投递带不可变 `event_id`、
   `delivery_id`、时间戳与 HMAC-SHA-256 签名；接收方必须按 `event_id` 幂等。
   2xx 才算成功，重试由 River 管理。签名 Secret 与 API key 分离并遵守 ADR-007。

## 后果

- 客户端生成、权限检查、审计和故障排查有单一契约。
- keyset 不支持任意跳页；接收方必须实现去重并容忍乱序。
- 回调地址管理不属于 Extension 自助 API，增加少量运维工作但关闭开放式 SSRF。

## 备选方案

- 各模块自定义错误与分页：拒绝，无法稳定生成客户端或统一防越权。
- OFFSET 分页：拒绝，大数据下性能和一致性不可控。
- Webhook exactly-once 或允许组件提交任意 URL：拒绝，前者不可真实保证，后者
  扩大重复消费和 SSRF 风险。

## 验证要求

- 契约测试覆盖统一错误体、cursor 过滤指纹、sales owner 绕过和 scope 缺失。
- SSRF 测试覆盖私网/重绑定/重定向；重复、乱序和重试投递必须保持业务幂等。
