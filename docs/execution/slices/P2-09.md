## 完整行为

1. 仅信任已由内部 provider adapter 验真的企微 OAuth 结果；HTTP body
   不得直接构造 verified login，未预录、停用或禁止登录的管理员 fail-closed。
2. 每次登录生成两个独立 256-bit 随机值：session 与 CSRF；浏览器只收到
   RawURL opaque token，`admin_sessions` 只保存 SHA-256，不保存、记录或响应
   任何原始 bearer 材料。
3. `aicrm_session` 固定 `Secure + HttpOnly + SameSite=Lax + Path=/`；
   `aicrm_csrf` 固定 `Secure + SameSite=Strict + Path=/`，前端必须将其回送为
   `X-CSRF-Token`。OpenAPI 固定 43 字符 token 形状及 403 响应。
4. session 有效性同时校验过期、撤销、账号启用、登录开关及
   `session_version`；任一不符即 401。默认 TTL 为 8 小时，构造时只允许
   1 分钟至 24 小时。
5. `POST /api/v1/auth/logout` 必须先通过 session 鉴权，再将 header CSRF
   与服务端 hash 绑定比对；成功后原子撤销 session、清理两个 cookie
   并返回 204。错误 CSRF 不撤销会话。
6. `GET /api/v1/auth/session` 只返回 `admin_user_id/role/staff_id`；密钥、
   provider 凭据、token hash 与原始 token 都不进 API。
7. P2-10 之前 `Authorize` 对任何 capability 一律 fail-closed；P2-11 只负责将
   本片的鉴权 middleware 按冻结顺序装配进最终 router。

## 数据边界

- `admin_users` 只存人工预录的企微主体、角色与启停状态；不存密码。
- `admin_sessions` 是 v2 新运行时表，与 G1-D02 已决定 `DROP` 的旧
  `auth_sessions` 不是迁移目标；旧 session、CSRF、scope 和凭据一律不导入。
- 表 ownership 归 `internal/auth`；`admin_sessions` 额外冻结
  `token_and_csrf_hashes_only`。
