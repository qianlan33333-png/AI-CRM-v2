## 分档生成合同

1. 提供 `aicrm-config --tier=<s|m|l> --output-dir=<dir>`，只接受小写
   `s/m/l`；缺失、重复、额外参数或不安全输出目录 fail-closed。
2. 每档生成 `postgresql.conf` 与 `aicrm.env`；目录权限 `0750`，
   文件 `0640`，通过同目录临时文件 + rename 原子替换。拒绝 symlink
   目录或目标，不跟随链接写到范围外。
3. `postgresql.conf` 精确包含详细设计表中
   `shared_buffers/effective_cache_size/work_mem/maintenance_work_mem/max_connections`。
4. `aicrm.env` 精确包含 API/worker pgx 池、六队列并发、
   `GOMEMLIMIT`、外发分块、swap 需求、S 档 heavy window 与
   critical `30s` timeout。M/L 保留相同 heavy window 默认值，可由后续
   已冻结设置界面改动，不手工改生成文件。
5. worker pgx 池始终等于六队列并发合计 + 至少 2；S/M/L
   分别是 `9/18/30` 与 `7/15/26`。
6. 生成的 env 不得包含 DSN、密码、token、cookie 或企微凭据；
   `AICRM_DATABASE_URL` 仍只能在运行时从外部环境注入。

## Compose 与 staging 脚本合同

1. `deploy/compose.yml` 只使用单一 app image 与 PostgreSQL 16.14，
   不引入 Redis、额外消息队列、微服务或 Kubernetes。
2. S 档启用 `combined` profile，以 `--role=all` 运行；M/L 启用
   `split` profile，以同一 image 分别运行 `--role=api` 与
   `--role=worker`。worker 不暴露业务端口。
3. PostgreSQL 挂载生成的 `postgresql.conf`；应用从生成
   `aicrm.env` 读非敏感参数，并要求运行环境显式提供
   `AICRM_IMAGE` 与 `AICRM_DATABASE_URL`，禁止默认凭据。
4. `scripts/staging_deploy.sh` 默认且本片验收只执行
   `--render-only`；生成、校验参数与打印不含 secret 的下一步。
5. 真正 `--apply` 必须同时有 `AICRM_ALLOW_STAGING_DEPLOY=1`、
   `AICRM_IMAGE` 和 `AICRM_DATABASE_URL`，且使用 `docker compose`；任一
   缺失都在调用 Docker 前 fail-closed，错误不回显 DSN。
6. 脚本不自动执行 live migration、生产操作或企微调用。
