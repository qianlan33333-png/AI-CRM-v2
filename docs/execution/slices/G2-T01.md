# G2-T01：可追溯的最小运行时镜像入口

## 输入合同

- Base SHA：`0c4c1bd697631d6242fdf838d17303970635144f`
- Phase：`G2` 部署准备
- slice_kind: infrastructure
- 决策锚点：`USER-STAGING-TARGET-2026-08-11`
- 初始 2C2G 测试目标已被用户换成新的 2C4G 目标机；后者满足 S 档
  CPU/内存基线，active swap 补足 4G 后再执行 S 档 apply。
- 不改变认证、secret、企微凭据、数据库迁移语义或六队列合同。

## 实现合同

1. 生成 Linux amd64、`CGO_ENABLED=0` 的单一 `aicrm` release binary；
   构建必须绑定干净 Git HEAD，并以 Go build ID 留下精确 SHA。
2. 输出只能写到仓库外的既存目录；拒绝相对路径、仓库内路径和 symlink
   目标，使用同目录临时文件后原子替换。
3. runtime image 使用 `scratch`，只包含该二进制，以固定非 root UID/GID
   `65532:65532` 运行；构建上下文只允许 `aicrm`。
4. image label 必须绑定 `org.opencontainers.image.revision`；部署方传入当前
   main 的 40 位 SHA。
5. 本片不新增 GitHub 部署 workflow。现有 repo-contract 在 bootstrap
   阶段禁止 workflow write/deployment 权限，该安全门保持不变。

## 验收

- 永久正例生成 release binary，并校验 GOOS、GOARCH、源码 SHA、clean tree
  和 SHA-256 收据。
- 永久负例覆盖相对输出与仓库内输出。
- Dockerfile 静态合同证明 scratch、非 root、固定 entrypoint、无可执行或
  可变层指令。
- focused gate、全量 CI、中文 PR、squash merge 与精确 main CI。

## 明确不做

- 本片只固化镜像入口，不预填服务器 apply、迁移或健康检查结果。
- 不连接生产数据库，不导入真实身份数据，不调用真实企微。
- 不在本片实现 Web 静态托管或真实企微 OAuth。

## correction

- `slice_induced=1`：Go 1.26 的交叉编译产物未按首版断言写入 VCS build
  metadata；改为在 clean-tree 前置下以精确 40 位 main SHA 作为 Go build
  ID，并由 `go tool buildid` 永久验收，绑定强度不降低。
- `verification_induced=1`：本机隔离 PostgreSQL 为 16.13，而硬门要求
  16.14；全量门在版本断言处正确 fail-closed，不降级版本检查，由 PR CI
  的固定 PostgreSQL 16.14 完成全门验证。

## 回滚

回滚本片 squash merge 将移除 release binary 构建器和最小 runtime
Dockerfile；不触碰服务器容器、卷或数据库。服务器回滚在部署证据中另记。
