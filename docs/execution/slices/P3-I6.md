  `merge_review` 永不自动重放。使用 `(version,id)` 公平排序和
  `FOR UPDATE SKIP LOCKED`，并在同一 transaction 锁定排序 identity IDs。
- 重放保留原 event type、payload、source、idempotency key 与 occurred_at，复用 I5 的
  唯一 active customer root 归因路径。成功时 Contact timeline、event_log 和
  `state=replayed/version+1/resolved_at` 同 UoW 提交。
- 零 root、多 root 或不可用 binding 时不写 timeline/event，将 version 加一但仍保持
  `state=pending/resolved_at NULL`，使后续 ready fact 不被饿死；同一 pending 后续仍可重试。
- transaction/event/pending completion 任一失败均整体回滚。相同 pending 的并发认领只允许
  一方执行，事务提交结果不产生重复 timeline 或 event。
