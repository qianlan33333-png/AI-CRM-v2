## 冻结行为

- Bind 复用 I1 v1 normalizer；不会为缺失 identity 或客户隐式建档。浮动 identity 与
  目标 Contact 均存在且可用时返回 `bound`，并在同一 UoW 追加一条不含 raw/normalized
  value 的 `identity.bound` event。
- 同一 identity 已绑定到请求客户时，另一幂等键返回 `already_bound`；同一幂等键的
  replay 返回原始完成结果且不再追加 event。相同幂等键而规范化 command 不同必须
  fail-closed，零新增副作用。
- identity 已绑定给另一客户、identity 不存在、目标客户不存在或已软删时返回不泄露
  客户 ID 的 `rejected`，并完成该 receipt。I3 不改写现有绑定。
- verified unionid 的实际 merge 仅由 I4 完成；verified phone 和无唯一 primary 的
  durable merge-review 仅由后续 review slice 完成。I3 不返回伪造的 `merged` 或
  `manual_review`，不创建 review、pending event、customer merge 或 replay。
- receipt reservation、identity edge、event 与 completed result 必须在一个
  transaction-bound UoW 中。receipt 的 key/payload 仅保存 versioned HMAC digest，
  不保存 raw identity 或 idempotency key。
