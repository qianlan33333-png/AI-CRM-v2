## 完整行为

1. settings registry 是 allowlist：`wecom.corp_id`、`wecom.agent_id`、
   `outbound.rate_per_second`、`outbound.max_attempts` 按各自类型和边界校验并规范化。
2. 被标记为 secret 的 key 和未知 key 在进入 UoW/数据库前 fail-closed；错误只含 key
   和规则，不回显输入 value。
3. 一次 Set 在同一 PostgreSQL transaction 内按 key 串行化，写 `settings`、追加
   `settings_audit(request_id)`，并调用 events Appender 写 `setting.updated`；任一步
   失败三者一起回滚。
4. 相同 request_id、key、actor 和规范值返回原审计结果且不重复写；复用 request_id
   表达不同事实返回 `ErrIdempotencyConflict`。
5. event payload 只含 setting key 与 audit ID，不含 old/new value；Get 对 secret key
   永远拒绝。
