# G2-T02：River staging migration 单向入口

## 输入合同

- Base SHA：`7cad6482516da7d4071ac98e2317e03dd2460238`
- Phase：`G2` 部署准备
- slice_kind: infrastructure
- 依赖：G2-T01 runtime image 入口已合并且精确 main CI 全绿。
- 本片只提供 River 官方 migration 的 staging `up` 入口，不改 migrations、
  River schema、公共 port、调度器或 worker。

## 实现合同

1. `aicrm-river-migrate --direction=up` 只接受唯一固定动作；down、缺失、
   重复或额外参数 fail-closed。
2. DSN 只经现有强类型 `config.Load(RoleAPI)` 读取；错误输出不得包含 DSN、
   密码或底层连接错误。
3. 使用受限 90 秒 context、最多 2 个连接，先 Ping，再调用既有
   `platformriver.Migrate(DirectionUp)`。
4. release builder 支持生成精确 main SHA 绑定的迁移二进制；runtime app
   image 仍只包含 `aicrm`，不扩大常驻攻击面。
5. 架构导入门仅精确增加 `cmd/aicrm-river-migrate` 为组装根；
   任意其他 `cmd/*` 仍禁止跨域导入，并以永久负例锁定。
6. 不自动执行 migration；服务器部署步骤在用户授权后显式调用并留证。
7. 分档 `postgresql.conf` 固定生成 `listen_addresses='*'`，使应用可从
   Compose 内部网络连接；PostgreSQL 端口仍不映射到主机或公网。

## 验收与回滚

- 单元测试覆盖成功、deadline、非法参数、配置错误、迁移错误与 secret
  不泄露；release gate 同时验证 app/migration 两个 Linux amd64 build ID。
- staging migration 前保留空卷删除回滚；迁移后回滚采用 staging 数据卷
  备份/重建，不在 CLI 暴露 River down。
