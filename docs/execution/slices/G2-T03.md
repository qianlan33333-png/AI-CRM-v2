## 实现合同

1. 固化精确 main SHA、main CI、镜像、迁移、运行时、端口和重启证据；不得在
   仓库记录服务器凭据、数据库密码或可复用 secret。
2. `package_release_archive.sh` 仅接受 40 位小写 SHA 根目录，验证全部
   `SHA256SUMS`、必需文件、无 symlink、单一 SHA 顶层目录。
3. 发布源或归档出现 macOS AppleDouble `._*` 文件必须 fail-closed；打包时
   同时设置 `COPYFILE_DISABLE=1` 与 `tar --no-xattrs`。
4. 归档输出只能写入源目录外的既存目录，经同目录临时文件原子替换，模式
   固定 `0640`。
5. 新归档门必须接入 `ci-go`，并配断连、空实现和 AppleDouble 永久负例。

## 部署边界

- 测试 API 只绑定字面 loopback `127.0.0.1:8080`；PostgreSQL 不映射主机

- 先启动 PostgreSQL，再执行 Goose up 与 River up，最后启动应用；不使用
  会在 migration 前启动应用的便捷脚本冒充本次真实顺序。
- 浏览器登录、Stages CRUD、真实 OAuth 与真实企微均保留
  `PENDING_EXTERNAL_GATE`。

## correction

- `infra_induced=1`：人工生成的首个传输归档携带 23 个 macOS AppleDouble
  元数据文件，Goose 在执行任何业务 migration 前 fail-closed。服务器将其
  原样隔离，真实文件 checksum 复验通过；本片增加永久清洁门。
- `slice_induced=2`：首版只把新目标接入 `ci-go` 并刷新 Makefile hash，
  repo-contract 负例证明断开该依赖后仍可刷新 hash 绕过。现已增加独立的
  目标唯一性、精确 recipe 与 `ci-go` 连接语义检查；另修正 manifest
  规范化中 BSD awk 对未转义 `/` 的解析错误。两项均以永久负例覆盖，未降低
  既有门禁。
- `verification_induced=5`：首次解包误判归档已剥离 SHA 顶层；PostgreSQL
  配置改属 UID 999 后普通用户 checksum 无读取权；应用无 Docker 原生
  healthcheck，故以真实 `/healthz` 代替不存在的 `.State.Health`；首次在
  staged index 上运行 release clean-tree gate 被正确拒绝；Web worktree
  首次调用未先注入根 `node_modules`。五项均未改业务实现或降低门禁。
