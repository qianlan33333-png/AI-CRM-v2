## Auth、表单与 DTO

- 唯一新能力是 `config.settings.manage`，仅 admin 获得 global scope，ops/sales
  fail-closed；`config.overview.read` 不能授权设置读写。
- 两个 GET 只要 human session + manage capability，不做 CSRF 校验。POST 同时要求
  A01 session-bound `csrf_token`、route-bound HMAC `admin_action_token` 和单值
  `confirm=1`。`operator` 只接收但忽略，actor 只来自 Principal。
- 设置目录严格闭合为 12 key：4 个非密 key 可读写，8 个 secret key 只返回
  `configured/masked` 布尔值。secret row 不含 value/display/source/version/时间/
  actor/request/audit 字段，代码不引入 Secret port 或 secret value。
- secret 动态字段缺失或 trim 后为空表示保持原值；任意非空 secret、未知 key、
  重复 field 均在第一次 Manager/UoW 前拒绝。成功与认证后的失败均用有限
  safe code 302 回原页，不回显输入值。
- JSON 资源固定 `ok/config/source_status=next_read_model/fallback_used=false` 且
  `Cache-Control: no-store`；metadata、summary 顺序、action type 与 audit latest 10
  保持中央绑定字面。非密 row 的 `version` 在缺值、有值及存在多条
  audit 时均固定为空字符串，不使用审计计数或任何派生值。

## 存储、幂等与迁移边界

- 仅查询 4 个非密 key；审计查询不 select `old_value/new_value/request_id`，
  只用 `old_value IS NULL` 投影 `create|update`，按 `updated_at DESC,id DESC`
  取 10 条。
- 提交在全量预校验后按 key 复用 Config Manager；actor 为 `admin:<id>`，
  request-id 为 `<platform-request-id>:<key>`。每个 key 保持现有
  `settings + settings_audit + setting.updated` 同 UoW，不宣称 form-level 原子性。
- `LEGACY-T14-024` 保持 `MANUAL_REENTRY/NOT_STARTED/NOT_RUN`。只记录
  `4_non_secret_keys`；legacy values/secrets/updated_at 皆 `imported=false`，
  `production_execution=false`。未读取旧数据，未构造 importer，未执行生产数据库。
