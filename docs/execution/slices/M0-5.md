## 目标

## 快照 v1 格式

catalog 是单个普通 JSON 文件：

```json
{
  "version": 1,
  "ignore_paths": [],
  "cases": [
    {
      "operation_id": "contacts.get",
      "case_id": "happy",
      "request": {"method": "GET", "path": "/api/customers/1", "body": null},
      "expected_response": {"status": 200, "body": {"id": "1"}}
    }
  ]
}
```

- `operation_id + case_id` 唯一，按两字段排序；未知字段和重复 JSON key 失败。
- `ignore_paths` 是排序后的精确 JSON Pointer。路径基于规范化视图 `/cases/{operation_id}/{case_id}/response/body/...`，只可指向双方都存在的标量叶子；禁止通配符、容器、重复或未命中路径。
- `validate` 校验 catalog；`compare` 从 stdin 接收 handler 测试生成的 ephemeral actual 文档。仓库不得保存手写 actual。
- 当前 `acceptance/snapshots/catalog.v1.json` 为零业务快照、零忽略项。P2 stages 片开始生成真实快照。

## 验收

- 相同响应通过；一个故意改变的响应字段以精确 JSON Pointer 失败。
- 未知字段、重复 key、重复 case、非法/扩大/未命中 ignore 与 symlink/FIFO catalog 失败。
- `make snapshot-gate-test` 接入 `ci-go`，repo-contract 锁定唯一入口、内容与 executable mode。
- ADR-001/ADR-010 只加 superseded-by 标记；ADR-011 记录被取代条款与 G1/P5 能力边界。
