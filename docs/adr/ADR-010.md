# ADR-010：功能矩阵状态与证据门分离

## 状态

Accepted（2026-08-08）

> 部分条款已由 [ADR-011](ADR-011.md) 取代：本文第 6 条的 `golden contract` 表述保留为历史记录，现行要求为行为快照。

## 背景

旧行为覆盖、实现完成和真实验收是三个不同事实。此前原型把无证据条目批量标成
merged/deprecated，既不能作为产品决定，也会让基础 CI 永久红或制造虚假进度。

## 决策

1. `docs/feature-matrix.csv` 每行一个稳定 `feature_id`，保留
   `page,section,action,triggered_api,expected_result,notes`，并增加：
   `disposition,implementation,verification,signoff,legacy_source_sha,source_evidence,
   decision_evidence,implementation_evidence,verification_evidence,target_feature_id`。
2. 三个正交状态列只允许：

   - disposition：`UNREVIEWED | MIGRATE | MERGED | DEPRECATED`
   - implementation：`NOT_STARTED | IN_PROGRESS | IMPLEMENTED`
   - verification：`NOT_RUN | SYNTHETIC_PASS | STAGING_PASS | PRODUCTION_PASS`
   - signoff：`NOT_REQUIRED | PENDING_HUMAN_SIGNOFF | APPROVED`

   首次盘点一律 `UNREVIEWED/NOT_STARTED/NOT_RUN`，不得继承 v3 的计数或判断。
3. `MERGED` 必须填写目标行、合并语义和人工签字；`DEPRECATED` 必须有旧源码证据、
   原因和人工签字。`IMPLEMENTED` 必须引用已合并 PR、merge SHA、测试证据以及实现
   路径；只有分支或 Pro 报告不能成立。
4. `SYNTHETIC_PASS` 必须标明数据生成方法和命令；`STAGING_PASS` 必须关联环境、
   精确构建 SHA、时间和人工/自动证据；`PRODUCTION_PASS` 只能由获授权的真实链路
   产生。截图是补充，不能替代可重放日志或断言。
5. 基础 `repo-contract` 只检查 CSV schema、枚举、唯一 ID、引用与证据字段一致性，
   不要求业务完成。P1 disposition 签字、P4 implementation 覆盖和 P5 staging
   验收使用独立 completion gate；尚未到门写 `PENDING_HUMAN_SIGNOFF` 或
   `PENDING_EXTERNAL_GATE`，不得伪造 PASS。
6. 矩阵更改必须在 PR 中逐行可见。行为语义变化同时更新对应 golden contract；
   不允许通过删除行、重编号或放宽断言让门变绿。

## 后果

- 仓库结构可先保持绿色，同时业务完成度仍被诚实暴露。
- 每项结论可追溯到旧事实、产品决定、代码和环境证据。
- 维护证据字段增加工作量，但消除“实现”“模拟通过”“生产通过”的混称。

## 备选方案

- 单一 done 列：拒绝，无法表达决策、实现和验证层级。
- 原型自动批量认定 merged/deprecated：拒绝，缺产品授权和行为证据。
- 把所有未完成项作为基础 CI 失败：拒绝，会迫使伪造状态或绕开质量门。

## 验证要求

- validator 负例覆盖重复 ID、非法枚举、悬空 target、缺 SHA/PR/签字证据和删行。
- completion gate 必须能区分 synthetic、staging、production 与未授权外部门。
