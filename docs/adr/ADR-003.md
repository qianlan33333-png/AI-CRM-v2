# ADR-003：使用 transaction-bound UoW 与 contact MergePort

## Status

Accepted — 2026-08-08

## Context

identity 负责判断两个外部身份是否应关联或合并，但架构铁律规定：

- identity 只能写 `identities`、`customer_merges`、`pending_events`；
- contact 才能写 `customers`、标签和时间线；
- 状态变更还必须在同一事务追加 `event_log`。

如果 identity 直接写 contact 表，会破坏所有权；如果通过三个独立 service 调用，又会在中途失败时留下半合并状态。需要既保持模块所有权、又保证单库原子性的协作机制。

## Decision

1. platform 提供 transaction-bound Unit of Work。UoW 在单一 PostgreSQL transaction 中执行 callback，并提供仅在 callback 生命周期有效的 transaction context。
2. transaction context 不得缓存、跨 goroutine、序列化或交给 River；callback 返回错误或 panic 时整体回滚。
3. identity 的 application service 是合并编排者：解析证据、选择业务结果，并在同一 UoW 内依次调用 identity store、contact `MergePort` 和 events port。
4. contact 的 transaction-bound port 至少承载：
   - `CreateForIdentity`：创建渠道中立客户；
   - `MergeCustomers`：标记被并入客户、归并客户字段/标签/时间线，并保留原始 customer ID 证据；
   - `AppendExternalEvent`：把已归因外部事件写入客户时间线。
5. events 的 transaction-bound `Append` 在同一事务写 `event_log`。
6. 新客户与首个 identity Bind 原子提交。自动客户合并、identity 重绑、`customer_merges` 审计、contact 归并和 `customer.merged` event_log 也原子提交。
7. 跨模块只依赖 port；identity 不 import contact store，contact 不包含 identity 判断。

### 合并事务顺序

1. identity 在事务中锁定相关 identity/customer 引用，并重新验证前置条件；
2. 确定 primary 与 merged customer，任何冲突立即退出；
3. contact `MergeCustomers` 执行 contact 所有数据的逻辑归并；
4. identity 重绑 identities，并追加不可变 `customer_merges`；
5. events `Append(customer.merged)`；
6. commit；提交后异步消费者才可观察事件。

具体锁顺序必须按较小 customer ID 到较大 customer ID，降低并发合并死锁风险。遇到序列化或死锁错误，UoW 只能按有界策略重试整个 callback，不能从中间步骤继续。

## Consequences

### Positive

- 模块保持表所有权，同时获得单库 ACID 原子性。
- 任一步失败不会留下“已重绑身份但客户未合并”等半状态。
- 合并逻辑可以用故障注入验证所有回滚边界。

### Negative

- transaction-bound port 比普通 service port 更复杂。
- callback 内不能执行慢外部调用，否则会延长锁持有时间。
- 并发合并必须遵守稳定锁顺序和有界重试。

### Neutral

- 该方案依赖单 PostgreSQL 数据库；这是已接受部署边界，不设计分布式事务兼容层。

## Alternatives Considered

### identity 直接写 contact 表

拒绝。实现短，但所有权铁律失效，未来修改无法隔离。

### 多个独立事务 + 补偿任务

拒绝。当前单库可以直接获得 ACID；引入 saga 会增加中间状态和运维复杂度。

### 通过领域事件最终一致合并

拒绝用于核心合并。客户与 identity 在事件处理完成前会出现矛盾归属，风险高于收益。

## Failure and Test Requirements

- 在 contact 归并、identity 重绑、审计写入和事件写入每一步注入错误，验证全事务无可见变化。
- 并发反向合并同一客户对，验证无双主、无重复审计；死锁重试有上限。
- 测试 callback 外使用 transaction context 会失败，且 UoW 内不允许外部网络调用。
