# P4 Commerce 本地兼容：S07 175/176/178/179/180/181 收据

## 实现依据

- 这六项复用已合并 PR [#407](https://github.com/qianlan33333-png/AI-CRM-v2/pull/407) 的真实 merge commit `4765eeaaf894c057795a2cbab2a234cbcc358e75`（`P4：订单与退款安全本地导出闭环`）；本收据不把当前本地候选声明为 PR、合并或上线。
- `cmd/aicrm/api.go` 只注册本地读取/导出边界：`GET /api/admin/orders`、`GET /api/admin/wechat-pay/orders`、`GET /api/admin/alipay/transactions`、`POST /api/admin/exports` 与 `GET /api/admin/exports/{job_id}`。
- `cmd/aicrm/legacy_order_board_api.go` 将微信支付、微信小店和支付宝筛选映射为 `wechat`、`wechat_shop`、`alipay` 的订单投影；导出只接受 `resource=orders` 与该 provider filter。
- `internal/order/app/board.go` 的导出在一个 UoW 内保留 actor-scoped idempotency receipt、local export job 与 Order event；`payments` 资源仍 fail-closed，接口没有 provider client，也没有退款执行路径。
- `internal/order/store/board_repository.go` 只查询 `order_list_projections`；本包不新增 migration、SQLC、OpenAPI 或 generated 输出。

## 聚焦验证

- `TestOrderBoardProviderListsUseReadRBAC` 通过完整 HTTP composition root 验证微信支付、微信小店、支付宝列表各自固定/传递 provider filter，且仅要求 `order.read`。
- `TestOrderBoardProviderFilteredExportsRequireCSRFAndUseServerActor` 对三种 provider 的通用 `POST /api/admin/exports` 验证缺失 CSRF 必须拒绝；有效 CSRF 时使用 session actor、`order.write` 与 Idempotency-Key，而不信任请求体 actor。
- `TestOrderBoardProviderFilteredExportIsReceiptBackedAndLocal` 验证三种 provider 的 export filter 到 store、同键回放只保留一个 receipt/job/event，且 CSV 是本地投影。

```sh

env -u BASH_ENV -u ENV GOWORK=off GOFLAGS=-mod=readonly GOCACHE=/private/tmp/aicrm-p4-commerce-gocache go test -race -count=1 -run '^TestOrderBoardProviderFilteredExportIsReceiptBackedAndLocal$' ./internal/order/app
```
