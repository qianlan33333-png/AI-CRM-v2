# P3-W2：企微 Callback 事件去重与稳定分发边界

## 输入与冻结合同

- Base SHA：`7a592c024a81698fa1b4fea33cff877fd0040081`，W1 #174 合并后的 application/go、application/web、policy/repo-contract、security/secret-scan 均为 success。
- 延续 `LEGACY-S06-043`、`LEGACY-API-0751` 与 `LEGACY-API-0780` 的两条既有 callback 路由；本片不增加 URL、OpenAPI operation 或管理 API。
- `docs/architecture/table-ownership.yml` 冻结 `event_log` 为 events 所有、仅 append/dispatch state；`events/port.Appender` 冻结为同一 UoW 的 idempotency-key append。W2 复用该合同，不引入 migration 或新的跨域 public port。

## 可观察行为

- 已完成 W1 验签、解密和 CorpID 校验的 `enter_agent` callback，只写入一个不含原始 XML、外部标识或 PII 的 `wecom.callback.accepted` 审计 outbox 事实。稳定键由 plaintext SHA-256 形成，同一事件重放只保留一个 `event_log` 事实。
- 已验签且结构有效、但不是允许事件的 callback，写入同样去重的 `wecom.callback.rejected` 审计事实后以稳定 `400 invalid callback` fail-closed；不会生成 encrypted success ACK。
- events River dispatcher 只把两类 callback 审计事实交给无副作用 audit subscriber；它不执行通讯录/外部联系人同步、Identity/Contact 写入、企微请求或外发。

## 硬边界

- 不修改 migrations、OpenAPI、`internal/*/port` 公共合同、UI 或 callback 路由数量。
- 不解析或持久化外部用户标识，不调用 Identity/Contact，不处理 `change_external_contact`，不做去重 inbox、同步、真实企微调用或生产数据库操作。

## 验证与回滚

- `make p3-w2-acceptance` 覆盖同一事件重放只持久化一次、未知事件审计后拒绝、HTTP 稳定错误与 callback audit subscriber 的无副作用边界。
- 回滚为 revert 本 PR；本片没有 migration、真实企微调用、生产数据库写或外部发送。
