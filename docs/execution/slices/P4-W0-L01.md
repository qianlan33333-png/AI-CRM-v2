## D01 基座复用与最小共享修复

- 直接复用 `event_deliveries`、named binding/backfill、claim/lease/retry/poison/
  `outcome_unknown`、River job、Delivery worker、Events public port 与 store-only SQL。
- Contact D01 producer 原先只接受 `automation.tag-trigger.v1`；第二真实消费者揭示该处仍
  硬编码单 consumer。L01 只在原 Contact UoW 内追加 `stats.tag-applied.v1` acceptance，
  任一 acceptance 失败时客户标签事实、customer event、event log、两个 delivery 与两个
  River job 全部回滚，不引入 registry 或泛化框架。
- Stats 只导入 Events public port；只有 Stats store/SQLC 写 `stats_daily` 与
  `stats_event_receipts`，不写 Contact、Automation 或 Events-owned 表。

## 投影与旧兼容边界

- `stats_daily` 字节级遵循冻结详细设计的 `(stat_date, metric_key, dims, value)` 合同；
  L01 只写 `metric_key=customer.tag_applied`、`dims={tag_id}` 的真实事件计数。
- `stats_event_receipts(event_id, consumer)` 是唯一幂等 receipt；reserve、projection `+1`
  与 delivery complete 同一 UoW。重领、River replay 或历史 backfill 不重复累计。
- 冻结 781/293 证据没有与该 tag-applied 指标一一对应且 DTO 已冻结的旧读取接口；按计划
  L03 才交付 dashboard compatibility APIs。因此 L01 以 Stats-owned repository/真实 PG
  黑盒核算作为可观察 projection 出口，不猜 DTO、不提前实现 L03、不虚假销账旧路由。
