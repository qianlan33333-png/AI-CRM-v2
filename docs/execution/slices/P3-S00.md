## 冻结语义

### 1. 人群与物化边界

- `segments.definition` 只保存 parser 验证并规范化后的 DSL v1 JSON 文档；
  `segment_members` 只保存由成功刷新得到的 OneID 投影。成员表不是身份快照、
  不是外部 ID 映射，也不允许人工编辑。
- Segment 独占写 `segments`、`segment_members`。它只读 contact 的
  `customers/customer_tags/tags`，不导入 contact 的 app/store/http，也不写 contact、
  identity、event_log 或 River 表。
- `refresh_mode=manual|scheduled`，scheduled 必须有非空 cron；`refresh_status` 只能
  为 `idle|running|failed`。S04 才冻结 cron 校验、River heavy job、并发刷新/替换成员和
  `member_count/refreshed_at` 的事务细节；本片不声称任何刷新已执行。
- 创建、更新、手工刷新命令都必须有稳定 Idempotency-Key。同 key 同规范化命令返回
  原事实；同 key 异命令 409 且无副作用。刷新接收只代表 durable command，绝不代表
  成员已更新或任何 outbound 发送。

### 2. DSL v1 AST 与规范化

根节点只能是下列三种闭合对象之一，不能混合键、不能有未知键或重复键：

```json
{"and":[{"field":"stage_id","op":"in","value":[2,3]}]}
{"or":[{"field":"tag_id","op":"has_any","value":[15,22]}]}
{"field":"last_interact_at","op":"before","value":"-7d"}
```

- `and` / `or` 的数组为 1–64 个子节点；全树最大深度 8、最大节点 128、所有数组
  value 合计最大 1000，JSON UTF-8 字节数最大 64 KiB。重复 JSON object key 必须拒绝，
  不得采用 last-key-wins。
- 字段、操作与值类型是精确白名单：

  | field | op | value |
  |---|---|---|
  | `stage_id` / `owner_staff_id` / `channel_id` | `eq` / `in` | 正 int64；`in` 为元素唯一、规范化后升序的 1–1000 正 int64 数组 |
  | `tag_id` | `has_any` | 元素唯一、规范化后升序的 1–1000 正 int64 数组 |
  | `added_at` / `last_interact_at` | `before` / `after` | RFC3339 UTC timestamp，或 `-[1-9][0-9]{0,3}d` |
  | `is_deleted` | `eq` | boolean |

- 不支持 `not`、空条件、JSONB `extra`、名称模糊匹配、外部身份字段、任意 SQL、任意
  函数、OFFSET 或隐式默认条件。时间相对值由一次编译请求的 UTC reference time 解析，
  之后只携带绝对参数；不得把 `now()` 或请求字符串嵌入语句。
- `and/or` 保留输入顺序以维持可解释性和稳定参数顺序；`in/has_any` 的整数值必须按
  升序规范化。语义相同但 value 未排序的输入可以规范化为同一定义；重复值、重复键或
  不可规范化输入一律拒绝。

### 3. 结构化错误

S01/S02 只能返回下列稳定 reason code，并以 `FieldError.field` 指向 JSON Pointer：

`segment_definition_invalid_json`、`segment_definition_invalid_shape`、
`segment_definition_duplicate_key`、`segment_definition_limit_exceeded`、
`segment_definition_unknown_field`、`segment_definition_unsupported_operator`、
`segment_definition_invalid_value`、`segment_definition_noncanonical_value`、
`segment_compile_unrepresentable`、`segment_compile_unsafe`。

客户端输入错误映射 422；JSON body/path/query 基础格式错误映射 400；幂等命令 payload
冲突映射 409。错误不得回显原始 DSL 全文、SQL、绑定参数或客户 ID。

### 4. S02 SQL 安全合同

- S02 的 compiler 只能将已验证 AST 映射为**闭合的固定 sqlc 查询族**和强类型 bind
  plan；运行时不得发射、拼接、format 或执行 SQL 文本，不能使用 ORM、动态 SQL builder
  或直接 pgx `Query/Exec/Prepare`。
- 所有可执行 SQL 只能位于 `internal/segment/store/queries/*.sql`，有 sqlc name block，
  并通过生成物调用。每一条涉及 `customers` 或 `customer_events` 的新增查询都必须由
  PostgreSQL 16.14 query-plan gate 以 generic plan EXPLAIN；任何目标 Seq Scan 失败。
- 所有用户值只能作为 typed bind 参数；字段、运算符、join、排序与 LIMIT 只能来自本页
  白名单。S02 不写表、不刷新成员、不调用外域和不提供第二个筛选实现。
