## 完整行为

1. `internal/platform/scheduler` 是唯一 River periodic job 生成入口；生产
   composition 只允许 `cmd/aicrm/scheduler.go` 构建一次不可变 plan。
2. 每个定义必须指定非空且唯一的稳定 ID、固定六队列之一、非空
   schedule 和已注册 worker 的 job args；队列错配、default、未注册 kind
   、重复 ID 全部 fail-closed。
3. scheduler 统一生成显式 queue options，调用方不得覆盖；运行时不
   暴露 raw River client，不允许通过 `Client.PeriodicJobs()` 动态绕过中央目录。
4. 本片只建立空的生产目录，不提前注册 dispatcher、segment、stats、wecom、
   outbound、pending replay 或分区预建任务；它们在对应功能片加入同一目录。

## 路径边界

允许 `internal/platform/scheduler/**`、`internal/platform/jobqueue/**`、
`cmd/aicrm/{components.go,scheduler.go}`、P2-05 acceptance、架构/source-policy 门禁与
负例、Make/repo-contract 收据、slice card/ledger。

不修改 OpenAPI、ADR、migration、业务 schema、dispatcher、业务 worker 或任何外部调用。

## 验收

- 表驱动覆盖空 plan、唯一 ID、非法/重复 ID、nil/typed-nil schedule 与
  args、未注册 kind、队列错配、default queue、options 覆盖和返回切片不得
  篡改 plan。
- 架构 lint 拒绝 scheduler 外的 River periodic 构建/动态注册，source-policy
  保持 `time.Ticker` / `time.AfterFunc` / 第三方 cron 永久负例。
- PostgreSQL 16.14 真实验收：两个 worker client 配置同一 stable ID 与
  RunOnStart 定义，只产生 1 条指定队列 job 且只执行 1 次，无 default job。
