## 完整行为

1. 所有已冻结 `/api/*` operation 逐项显式绑定 P2-10 capability；健康检查
   保持公开。未知路由和错误 method 返回 ADR-006 允许的统一 JSON 错误体。
2. 固定执行顺序为：请求 ID → session 鉴权 → operation 授权 → 单账号并发
   预算 → 超时 → panic recovery → 统一错误码 → 结构化访问日志。路由注册不得
   依赖 default capability 或路径前缀推断。
3. 单账号进程内预算默认 4，不排队；同账号第 5 个在途请求立即返回
   `429/CONCURRENCY_LIMITED`。不同账号互不占用，正常、错误和 panic 返回均须
   释放槽位；缺少已认证 account context 时 fail-closed 为 401。
4. 默认请求超时 10 秒，允许构造 Gateway 时为专项验收注入更短时长；非法预算
   或超时配置拒绝构造。handler 必须遵守 context cancellation，超时统一映射为
   ADR-006 已冻结的 `503/DEPENDENCY_UNAVAILABLE`，不得返回标准库文本错误页。
5. API role 使用独立 pgx pool、真实 HTTP listener 与有界 graceful shutdown；
   worker role 不装配 listener，`all` role 仍各自拥有独立 pool。

## 验收

- 永久单元测试覆盖同账号 4+1、跨账号隔离、槽位释放、缺 account、非法配置、
  timeout JSON、panic 释放与请求 ID。
- 黑盒 acceptance 通过实际 router 证明：health 公开；全部十个 operation 缺
  session 均 401；同账号第 5 个请求 429；timeout 为 503；路由模板日志不含原始
  URL/query/PII。
- composition root 测试证明 listener 仅由 API role 构造并在取消后有界退出。
- focused race tests、全量 CI、Web、repo-contract 永久负例、secret scan、
  中文 PR、squash merge与精确 main CI。

## 明确不做

- 本片不改变鉴权模型、cookie/CSRF、secret/企微凭据处理，也不增加登录 provider
  或真实 OAuth exchange。
- 本片不实现 Web shell、页面、stages 或 P3 业务 handler；未实现 operation 在
  完成鉴权、授权与网关链后仍保持 501。
- 不连接生产数据库、不部署、不调用真实企微、不执行 live migration。

手写范围目标低于 P2 的 `12 files / 800 lines`；测试、生成物、文档、收据与
ledger 按既定口径排除。
