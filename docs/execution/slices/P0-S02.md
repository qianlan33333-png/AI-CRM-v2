# P0-S02：healthz strict handler

状态：`READY_AFTER_P0_C04_MERGE`

执行模型：`root` 冻结合同、派发并独立验收；`gpt-5.6-terra`（`ultra`）仅在派发后实施。

- executor_task_id：`EXECUTOR_TASK_ID_ASSIGNED_AT_DISPATCH`
- worktree：`WORKTREE_ASSIGNED_AT_DISPATCH`

## 1. 背景与单一目标

P0-S01 已提供 role 与进程生命周期骨架。本 Slice 只实现由冻结 OpenAPI 生成的
`GET /healthz` strict handler，使进程存活响应具备编译期类型约束和确定性 JSON。

本片不把 handler 接到 `cmd/aicrm`、listener 或真实端口；完成后只能称
`LOCAL HANDLER CONTRACT`，不能声称应用已启动 HTTP 服务、可供 staging/production
探活，或数据库/River 已就绪。

## 2. 精确基线、root 派发与权威输入

- base SHA：`P0_C04_MERGE_SHA_PENDING`
- `executor_task_id` 和 `worktree` 只由 root 在派发时写入；在此之前不得伪造
  task ID、worktree、实现 diff SHA 或文件 manifest SHA。
- root 只向内部 `gpt-5.6-terra`/`ultra` 派发一个独立 worktree；Terra 不使用
  本中央 worktree，也不从压缩包、外部补丁或外部交接物取得输入。
- Terra 完成后返回完整相对路径文件 manifest 与命令原始日志。root 在独立验收
  worktree stage 该 manifest，才计算 canonical
  `git diff --cached | shasum -a 256`；该值是未来 P0-S02 实现 diff，不是
  P0-C04 当前中央合同 diff。

权威输入：

发现中央契约错误时只提交问题报告，不得修改中央文件。

## 3. 允许修改路径

只允许新增以下 2 个普通、非符号链接文件，不得含 group/other execute，合计不超过 180 行且零新增依赖：

1. `internal/platform/http/health.go`
2. `internal/platform/http/health_test.go`

其余路径全部禁止，尤其是 `.github/**`、`cmd/**`、`go.mod`、`go.sum`、
`tools/**`、`api/**`、生成目录、migrations、ADR/架构、公共 port 与 Codex
验收夹具。

`internal/platform/http` 顶层只允许普通非链接的 `contract.go` 和上述两文件；不得增加其他 entry。
`contract.go` 只是 Codex 冻结的 package 锚点，用于保证实现缺失时
`go mod tidy` 仍可离线解析 tagged acceptance；不得修改或把实现放入该文件。

## 4. 冻结实现合同

- package 名为 `platformhttp`。
- 导出面仅限无状态 `HealthHandler`、`NewHealthHandler` 与必需 `GetHealthz`；测试仅允许 `Test*` 导出函数。
- 编译期断言 `*HealthHandler` 实现 `generated.StrictServerInterface`。
- 实现签名必须直接来自生成接口：
  `GetHealthz(context.Context, generated.GetHealthzRequestObject)`。
- 每次确定性返回 `generated.GetHealthz200JSONResponse{Status: generated.Ok}` 与
  `nil`；不得手写状态码、JSON、响应头或替代 DTO。
- `/healthz` 只是 process liveness。上述两文件均不得查询 DB、River、settings/env、
  网络、文件、时间、主机名、版本、uptime 或 readiness，不得启动 goroutine/listener/timer。
- 不修改生成物，不注册 router，不改 `cmd/aicrm`，不加入日志或中间件。

HTTP 200、`application/json` 与精确 `{"status":"ok"}\n`。

## 6. Internal Terra 执行、交付与禁止操作

Terra 只在 root 派发的独立 worktree 实施，直接留下允许的两个文件，不上传压缩包、
外部补丁或其他附件。回复必须给出完整文件 manifest、逐命令 stdout/stderr、
退出码、手写行数及未执行项；不得把任意 `P0-C04` 中央 diff 当作实现交付物。

Terra 不执行 Git/GitHub、安装或升级依赖、部署、数据库/网络/外部调用或真实数据
操作；不得把 `httptest`/local 写成真实 HTTP、staging 或 production PASS。未执行
写 `NOT EXECUTED`。root 独立复核 manifest、stage 后的 canonical diff SHA、所有
本地门禁，以及后续获授权的 Git/GitHub 操作。

## 7. 验收标准

- 只新增 2 个无 group/other execute 的普通非链接文件，合计不超过 180 行，依赖/锁文件零变化。

- race/vet/test/build/generate/mod/vulnerability 门均真实通过。
- root 独立复验、中文 PR、远端 CI 全绿后才可 squash merge。
- 本 Slice 不产生部署、真实端口、真实数据库或真实企微证据。
