## 冻结行为与边界

- `dispatching` 回执与任务 `sending` 同事务；最终回执、`sent` / `retryable_failed` / `final_failed` / `outcome_unknown` 任务终态及 `outbound.sent` / `outbound.failed` 事件同事务。
- `attempt_count` 仅是已经开始的 provider attempt 审计计数；不保存 `next_retry_at`，也不在 O5 创建任何 River 重试 job。
- 完成回放使用数据库 `completed_at` 和 attempt ID 重建同一事件事实；并发或响应丢失回放返回原状态、原事件，provider 仍只调用一次。
- 事件追加失败会回滚最终回执与任务终态，保留已提交的 `dispatching` / `sending`；后续回放保守落 `outcome_unknown`，绝不盲重试。
- 只使用验收内测试 provider；绝不执行真实外发。不含 O6 重试/取消、O7 API、O8 UI、批量新语义、OpenAPI、public port、root dependency、生产数据库或 live migration。
