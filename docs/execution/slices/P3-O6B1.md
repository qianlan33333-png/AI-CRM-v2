# P3-O6B1：pending 外发任务取消

## 输入与目标

- Base SHA：`233777fdb7b0bfeb3bc2c62d21e70e024abe4f34`；开工时 origin/main 三项 required CI 全绿且 open PR 为 0。
- 目标：只交付 `pending` task 的幂等取消。取消先赢时在 provider 边界前删除 River job，并在同一 UoW 提交 `cancelled` task、`outbound.cancelled` event、control receipt 与 task/job link；worker/dispatch 先赢时返回稳定冲突。
- 连续 migration 为 `00023`，仅新增 Outbound 自有 `outbound_task_job_links` 与只允许 `cancel` 的 `outbound_control_receipts`；不提前携带 manual retry。

## 冻结行为与边界

- 只允许 `pending → cancelled`。`sending/sent/retryable_failed/final_failed/outcome_unknown/cancelled` 全部拒绝，错误分别稳定为 task not found、transition conflict、worker won、idempotency payload conflict。
- 相同 `(idempotency_scope,idempotency_key,task_id)` 重放返回原 receipt/event/job/status；相同 key 异 task 冲突，不重复 event、provider 或 River catalog 变化。
- task 行锁是 provider 边界。正常路径从 Outbound 自有 generation link 取得 job；历史单条任务由 migration 从 enqueue receipt / send marker 回填；历史 batch pending 无 link 时，platform/jobqueue 仅用 River 官方 `JobListTx` 分页和 typed args 定位。
- 删除只能调用 River 0.24.0 官方 `JobGetTx` / `JobListTx` / `JobDeleteTx`；non-generated Go 不直接 `QueryRow/Exec`，Outbound SQLC corpus 不读取或写入 `river_job`，不新增动态 `Where`、万能 port 或第二调度器。
- 不含 manual retry、HTTP API、O7/O8/UI/OpenAPI、新产品能力、生产 DB、live migration、真实企微或真实外发。

## 迁移与黑盒验收

- C07/55432（PostgreSQL 16.14）从 exact-main 水位 22 升到 23；正常/边界/错误覆盖单条与 batch pending、双连接同 key、丢响应重放、异 payload 冲突、全部非法状态、event rollback。
- 真实 River 双胜序：cancel 先赢后真实 client 不进入 provider；真实 sender 已进入 provider 边界时 cancel 稳定冲突，worker 原调用完成且 provider 仅一次。
- 带已完成 cancellation 数据执行 `23→22→23`，receipt/link/event/task 事实不丢，已删除 River job 不复生、无 River FK；O6A 真实 attempt 1+2 的 `22→21→23` 与 O4/O5 兼容继续通过。
- 独立 Agent 不读取 migration 源码，对最终水位 23 只读 catalog 复核 PASS；复核时完成态取消数据已被后续夹具清理，因此不虚报独立 data-level PASS，数据事实由上述带完成 cancellation 的 `23→22→23` 黑盒验收证明。

## Route / matrix 映射

- O6B1 不新增 HTTP route，因此不把 legacy cancel route 或 feature matrix 行虚报为已实现。
- O7 将调用本片真实 service，并在具有 route、PR/SHA 与 normal/boundary/error 黑盒证据后精确维护 legacy route/matrix。

## 修正归因与外部门

- `slice_induced=0`，`infra_induced=0`，`scope_induced=0`。
- `verification_induced=5`：首次 PG 负例把共享 `event_log` 的既有取消事件误计为当前 case，收紧为当前 receipt join；回滚断言同一参数同时用作 bigint 与 JSON text 比较导致 SQLSTATE 42883，改为显式 bigint→text；首次 ownership 门发现验收夹具直接把 River job 改为 running，改用真实 River client + sender worker 形成两种胜序，未增加 lint 例外；两次手工静态门调用分别传入了 source-policy 不接受的 package 参数和 ownership 不支持的 `-config`，均改用仓库 canonical Make target 通过，实现无改动。
- 外部门：`REAL_WECOM_NOT_EXECUTED`、`OUTBOUND_EXTERNAL_EFFECT_NOT_EXECUTED`、`PRODUCTION_DATABASE_NOT_EXECUTED`、`LIVE_MIGRATION_NOT_EXECUTED`、`DEPLOYMENT_NOT_EXECUTED`。
