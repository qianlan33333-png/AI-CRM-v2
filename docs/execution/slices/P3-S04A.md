## 可观察行为

- `RefreshOnce(ctx, segmentID, referenceUTC)` 只接受正 SegmentID 与稳定非零 UTC reference；
  reference 在整个 UoW retry 中保持不变，relative-day DSL 因而不会漂移。
- 先用 `SELECT ... FOR UPDATE` 锁定 Segment，再以既有 closed parser/compiler/executor 得到排序、
  去重的 OneID；SQL 仅来自 S03 固定 query family 与本片四条固定 sqlc mutation，禁止 raw SQL、
  identifier、ORM、动态 builder 或第二份 filter-to-SQL。
- replacement 采用 delete + typed `bigint[]` insert + summary update；空集合是合法完整替换。
  同一 Segment 并发刷新由行锁串行化。任一解析、查询、写入或 event append 失败时，旧 members、
  summary 与 event_log 必须整体回滚。
- 成功提交后 `member_count` 等于实际集合大小，全部 `computed_at`、`refreshed_at` 与 `updated_at`
  等于 reference，`refresh_status=idle`；同 Segment/reference 的事件键稳定且同事实可幂等重放。
