# P3-O4：测试 Provider 驱动的外发 Sender

## 输入与目标

- Base SHA：`9e64a64ad62d68c155e675c86c999973596f3d2b`，O3 #188、I7 #190 与 S6 #189 已 CLOSED 且该 exact-main 三门成功。
- 目标：消费既有 O2 `outbound_enqueue_one` 与 O3 `outbound_enqueue_batch_task` River job，经共享 token bucket 后调用可注入 provider adapter，并在 Outbound UoW 中持久化稳定发送尝试结果。
- 连续 migration 固定为 `00020`；只新增 Outbound 所有的 `outbound_send_attempts`。

## 冻结行为与边界

- provider 边界前先提交 `reserved` 收据，再原子推进为 `dispatching`；provider 返回后，在独立 UoW 原子落 `succeeded`、`retryable_failed`、`final_failed` 或 `outcome_unknown`。
- timeout、connection、无响应体 5xx 与 adapter 异常归 `outcome_unknown`；429/临时错误归 `retryable_failed`；参数错误/好友失效归 `final_failed`。
- 已完成 River job 重放直接返回原收据；`dispatching` 重放保守落 `outcome_unknown`，绝不再次调用 provider。结果事务回滚后重放也不得二次外发。
- O4 只交付注入式 adapter contract 与验收内测试 provider，不提供真实企微 adapter、密钥或 runtime mount；绝不执行真实外发。
- 不改 `outbound_tasks` 业务状态、不追加 O5 状态事件，不含 O5-O8、重试/取消、批量新语义、API、UI、OpenAPI、public port、root dependency、生产数据库或 live migration。
