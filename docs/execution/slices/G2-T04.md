## 实现合同

1. Web 与 API 必须同源 HTTPS；Caddy 自动申请公开证书，只允许反代
   `/api/*` 与 `/healthz` 到字面 loopback `127.0.0.1:8080`。
2. PostgreSQL 继续无宿主端口映射；边缘进程使用独立无登录用户、
   `NoNewPrivileges`、strict filesystem protection 与仅 `NET_BIND_SERVICE`
   capability bounding set。
3. Web 发布目录只读挂载；SPA fallback 固定到 `index.html`，静态资源可长期
   缓存，HTML/API 默认 `no-store`。
4. 固化 CSP、HSTS、nosniff、deny framing、no-referrer 与最小
   Permissions-Policy；Caddy admin API 关闭，不启用访问日志记录原始 URL。
5. 运行时 Caddy 固定为官方 `v2.11.4` Linux amd64 发布资产，并核验 GitHub
   release digest `c41708ffb4af9bc6d19f7d22a7a034804352a21ecc62e1d3dfe3d58e30b38a3e`；
   不使用浮动包源或第三方镜像源。
6. 正例与 root user、loopback、CSP、broad capability 永久负例接入 `ci-go`。

## 验收边界

- 本片代码验收不伪造已部署、证书或浏览器结果；合并并绑定精确 main CI 后

## correction

- `slice_induced=2`：首版静态 checker 将 tab 写成普通转义文本，正例立即
  fail-closed；改为 Bash ANSI-C 字符串并以永久正例复验。首次部署又发现
  `/opt/aicrm` 为保护运行配置保持 `0750`，独立 edge 用户不能穿越；不放宽
  secret 父目录，改用 root-owned、world-readable 的 `/var/www/aicrm` 发布根。
- `infra_induced=1`：测试服务器访问 Docker Hub 超时，未使用不明镜像源；
  改为校验官方 GitHub release digest 后安装独立二进制与 hardened systemd。
- `scope_induced=0`
- `verification_induced=2`：首次在 staged index 上运行完整 `ci-go`，发布二进制
  clean-index 门按设计拒绝；先形成可审提交后再从 clean index 重跑，不绕过门禁。
  首次精确 SHA Web 构建在仓库根查找 `dist`，而实际输出为 `web/dist`；修正
  验证路径后从同一 SHA 重建。因此最终 `verification_induced=2`。
